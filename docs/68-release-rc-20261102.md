## 7. drain と切戻し

**②を閉じる順（検証環境。本番は初めから off）**
1. `RESOLVE_PATH_MODE=drain`、③は `ASSIST_SESSION_MODE=drain` で再起動する。新規は 409、既存の結果の受付と終了処理は動く。
2. `AUDIT_DATABASE_URL=… node scripts/report-drain-status.mjs --allow-db=<DB 名>` を流す。
   - 終了コード 0: off へ進める。3: 終わっていない処理がある。待つ（待ち時間は実行の期限 2 分、③は docs/63）。
   - 4: 結果不明がある。**待っても消えない。** 実行の有無を人が確認してから `--accept-unknown` を付ける。
3. `off` にして再起動する。

統合試験で確かめた。**実端末と本番では未確認。** 定期処理は放置された提案を閉じるが、判断待ち（`waiting_continue`）は閉じない。

**本番の切戻し**
1. `98f80ec`（または main の直前の SHA）をビルドして再起動する。
2. **スキーマは戻さない。逆 DROP を通常の切戻しにしない。** 追加スキーマのままで旧アプリの全試験が通ることを確かめた（§4）。
3. **注意:** `98f80ec` へ戻すと、端末コマンド入口と `/api/resolve` がまた開く。#130 の前の状態に戻るだけで、悪化はしない。
4. 復元が要るときは、配備の直前に取ったバックアップを使う。手順は docs/09 §4。

**環境の読み込み:** `api.conf` をシェルで読まない。`node scripts/run-with-env-file.mjs ~/.config/ai-helpdesk/api.conf -- <command>` を使う（値に `|` があっても解釈しない。ファイルの値を優先する）。
