## 1. 目的

1. 公開URLの**アクセス・ログインから**、一般社員の入力（STEP1〜3）→ AI一次対応 → 引継ぎ（STEP4）→ DX担当者の対応（STEP5）→ ナレッジ化・承認（STEP6）→ 完了（STEP7）までを**一気通貫**で実証する。
2. 引継ぎプロセス（STEP4〜7）を、**指定DX 1名（B1）を引継ぎ担当者**として詳細に検証する（宛先プルダウンに DX 5名が表示されることは別途確認）。
3. STEP1〜3 の**AI解決ルート**（担当者へ渡さず完了）も一気通貫で検証する。
4. 完了後に**最終報告書（HTML/PDF）**と**ナレッジ（下書き→承認→検索反映）**が正しく作られることを検証する。
5. 検出した不具合は重大度を付け、修正→再検証まで閉じる。

### 対象外
- Herald OS の導入評価（別件・N 判定済み）
- RSP 本体・MeshCentral の実セッション操作（連携界面の疎通のみ）
- 負荷試験（同時100ユーザー等）とペネトレーションテスト

### 引継ぎプロセス（STEP4→7）の詳細チェック列

1. **STEP4 共有**: 同意 → 宛先（B1 を選択。プルダウンには DX 5名）→ メモ → スナップショット → 通知キュー → `pending`

3. **claim**: B の状態へマージ／別担当は 409／状態未保存は 409→リトライ
4. **STEP5 対応**: 担当開始（`in_progress`）→ AI追加質問（A の文脈のみ）→ 対応記録 → （任意で端末コマンド/RSP）
5. **STEP6 承認**: 下書き → 承認申請 → **別の DX メンバー**が承認 → `completed`／自己承認は警告／一般社員は 403
6. **STEP7 完了**: 報告書 HTML/PDF → 監査 → KB 検索反映
7. **事後**: 完了報告の再発行・KB 下書きのリンク・一覧/統計の整合
