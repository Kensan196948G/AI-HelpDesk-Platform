## 4. 見つかったこと

### 4-1. 共有のテスト DB `ai_helpdesk_test` では 1 件失敗する

最初に `.env.test.local` の `ai_helpdesk_test` で全テストを実行したところ、**119 files 中 1 file / 2202 tests 中 1 test が失敗**した。

- 失敗: `apps/api/src/lib/knowledge-search.integration.test.ts`「期待される KB を、下限で落とさない」。
  相談 `kb-10`（共有フォルダ）の期待 `KB-2026-0001` が上位 3 件から押し出された。
- 原因: この DB には過去の試験が作った `knowledge` が残っている（`approved` 89 件 / `draft` 40 件。シードは 9 件）。
  「共有フォルダ」を題にした承認済み KB が多数あり、検索の上位を占める。
- 新規 DB では同じテストが pass する（§3）。CI も毎回新しい DB を使うので緑である。**製品コードの回帰ではない。**
- 今回の全テスト実行も、この DB に migrate・seed・試験データを書き込んでいる。
- 対処は未実施。この DB を作り直すか、ローカルの全テストは毎回新規 DB で行う運用にするかは別途決める。

### 6-2. 本番への書き込みが無かったことの確認

- このブラウザから本番 API へ届いたのは `GET /`・`GET /ops`・`GET /legacy`・`GET /api/me`・`GET /api/ops/status` の 5 件で、すべて 200（本番 API の journal、16:55 以降）。
  同じ時間帯の `POST /api/device/agent` 1 件はこのブラウザが呼んでいないエンドポイントで、送信元は調べていない。
- 上の GET がサーバ側で書き込まないことはソースで確認した。認証（`auth/ui.ts`）と `/` の読み込み処理に INSERT / UPDATE / 監査の追記はない。
  ルート定義のテキスト検索では、GET 54 本のうちハンドラ内に書き込みの文があるのは `GET /api/device/command` だけで、今回は呼んでいない（呼び出し先の関数までは追っていない）。
- 新 UI は画面を切り替えただけでは API を呼ばない（切替中の通信は Cloudflare の計測ビーコンのみ）。
- 新 UI はブラウザの `localStorage` に画面の状態を書く。これは使ったブラウザのプロファイル内だけの変化である。

### 6-3. 見つかったこと

1. **`/legacy` は「読み取りのみ」では開けない。** 旧 UI は、ブラウザで開くと読み込み直後に `PUT /api/state/:name`（状態の同期）と
   `POST /api/device/browser`（端末情報）を自動で送る（`prototype/bridge.js`、`prototype/device-bridge.js`）。
   このため今回は HTML を GET で取得しただけで、**旧 UI の画面表示と主要操作は未確認のまま**である。
2. **システム設定の「既定値から変更されています」。** 受け取った設定値は画面の既定値（`DEF_SET`）とすべて同じだったが、この注記が表示された。
   画面は設定オブジェクトの有無で判定しており、サーバは保存行が無くても既定値を返す（`loadSettings`）。本番に保存行があるかは確認していない。
3. **移行バナーの文言が現状より古い。** 「①受付と②AI一次対応は実データに接続済み。その他の画面は順次接続します」のままで、
   この文言は P2（PR #173）から変わっていない。その後の P3〜P12 でナレッジ・監査・Skills・設定・端末台帳も実データになっている。

いずれも今回は修正していない。
