## 3. 実装

### 3-1. `scripts/dist-manifest.mjs`: `--verify --root <absolute path>`

**目的**: docs/83 §10 の独立再監査で唯一 FAIL だった「repo の CLI で release の manifest を検証すると、release ではなく repo の dist と突き合わせてしまう」を解消する。**release 配下のコードを実行せず**、repo 側の CLI で release の dist を検証できるようにする。

| 契約 | 内容 |
|---|---|
| モード | `--root` は `--verify` 専用。`--write` との併用・重複指定・値欠落は `ARGUMENTS_INVALID`（usage 表示、exit 2） |
| `--commit` | **`--root` 指定時は必須**。省略は `ARGUMENTS_INVALID`（exit 2）。省略時に repo HEAD を暗黙の期待 commit にすると「別の木を基準にする」事故が再発するため |
| パス | 絶対・`path.normalize(p) === p`・制御文字（≤ 0x1f）なし。違反は exit 2。**root 自体の symlink（`current`）は受理**し、dist 内部の symlink は既存の `collectDistFiles` が拒否する |
| 既定 | `--root` 未指定時は従来どおり `path.resolve(import.meta.dirname, '..')` を repo root として検証（退行なし） |
| エラー | 引数エラーは exit 2、対象不正は exit 1。既存コード（`FILES_MISMATCH` / `COMMIT_MISMATCH` / `DIST_MISSING` 等）を変更しない |

使い方（release 検証の例。release のコードは実行しない）:

```bash
REL=$(readlink -f ~/ai-helpdesk-prod/current)
REF=<release の manifest.commit（40 hex）>
node scripts/dist-manifest.mjs --verify \
  --manifest "$REL/dist-manifest.json" --root "$REL" --commit "$REF"
```

### 3-2. `ops/systemd/ai-helpdesk-proxy.service`: `Wants=` を削除（H-1 / U-5）

- 変更前: `After=network-online.target ai-helpdesk-api.service` / `Wants=ai-helpdesk-api.service`
- 変更後: `After=network-online.target ai-helpdesk-prod-api.service` のみ（`Wants=` なし）
- 理由: `Wants=` は **disable 済みの unit も起動する**。rollback 後は prod unit が disabled でも unit ファイルと `current` が残るため、proxy を再起動すると prod が引き上げられて 18950 を奪い、**rollback が黙って巻き戻る**。`Wants=` を prod に付け替えるだけでは危険クラスが移動するだけで消えない。
- 起動順序: prod unit も proxy も `WantedBy=default.target` なので、`After=` で boot transaction 内の順序は成立する。上流が落ちている間も proxy は 502 を返して稼働を続ける（`Restart=always` の crash loop にしない）。
- **本番 unit への反映は未実施**（§5 P1）。実測: 稼働中の `ai-helpdesk-proxy` は今も `Wants=ai-helpdesk-api.service` を保持し、旧 unit は `not-found`。したがって現時点で引き上げ事故は起きないが、rollback で旧 unit を戻すと構造が復活する。

### 3-3. `scripts/set-smtp-password.sh`: 再起動対象の決定

- 変更前: 常に `ai-helpdesk-api.service` を再起動（本番切替後は `not-found` のため、SMTP_PASS 更新後の再起動で失敗し「設定は更新済み・再起動未実施」になり得た）。
- 変更後: **書き換え前**に再起動対象を決定する（原子性）。対象は `systemctl --user is-active` で判定し、active が 1 個ならそれ、0 個は「SMTP_PASS は未更新」で exit 1、2 個は `--unit` を促して exit 1。`--unit <name>` で明示指定できる（`[A-Za-z0-9_.@]` 始まりのみ、先頭 `-` は拒否）。systemctl 呼び出しは `--` で option 注入を防ぐ。
- restart 失敗時は「SMTP_PASS は更新済み」を明示して exit 1（`set -e` による無言 abort を解消）。
- 回帰テスト: `scripts/set-smtp-password.test.mjs`（10 tests、偽 systemctl + 一時 HOME で実 systemd に触れない）。

### 3-4. `scripts/install-proxy-service.sh`: health を唯一の hard gate に

- `api.conf` 不在は exit 1（PROXY_SECRET なしでは成功し得ない）。mode が 0600/0400 以外は**警告のみ**。
- 上流 unit（prod / legacy）の active 状態は**表示のみ**（非致命）。legacy 構成のホストで installer を回帰させないため。
- `curl --noproxy '*'` による health を**唯一の合否**とし、失敗時は上流 API と PROXY_SECRET の確認、`systemctl status` / `journalctl` の案内を出して exit 1。
