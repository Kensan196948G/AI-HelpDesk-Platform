## 変更

### 1. DB 所有証明（M1）

- `scripts/verify-isolated.sh`: 新規 DB の作成と `current_database()` の照合後、32 byte hex の `SMOKE_OWNER_TOKEN` を生成し、`COMMENT ON DATABASE "<DBNAME>" IS 'smoke-owner:<token>'` を刻印する。token は argv に出さず psql へ **stdin 経由**で渡し、`shobj_description(oid, 'pg_database')` で刻印を確認する。`AIHD_SMOKE_OWNER_TOKEN` は staging-smoke の直前まで env に載せない。
- `scripts/staging-smoke.mjs`: 起動前に `postgres` で `shobj_description` を読み、`smoke-owner:<token>` と完全一致しなければ `SMOKE_DB_OWNERSHIP_FAILED`。token 形式は `^[a-f0-9]{64}$`。**DB への書き込みはせず、読み取りだけ**を行う。
- `scripts/lib/smoke-guards.mjs`（新規）: token 形式と owner comment の一致を判定する純粋関数。DB・ファイル・環境変数に触れない。

### 2. dist 束縛（M2）

- `scripts/lib/dist-manifest.mjs`（新規）: `apps/api/dist` の regular file のみを再帰列挙（symlink・非 regular は拒否）し、repo 相対 path・bytes・sha256 から canonical manifest `{version: 1, commit, files, sha256}` を生成・検証する。manifest は 1 MiB、1 file は 512 MiB、件数は 10,000 を上限とし、キー・型・path 形式・昇順・sha256 の再計算・commit 40 hex を検証する。
- `scripts/dist-manifest.mjs`（新規 CLI）: `--write` / `--verify` と `--manifest <絶対 path>`。書き出しは `O_NOFOLLOW`・mode 0600 で、commit は明示指定か `git rev-parse HEAD`。
- `scripts/verify-isolated.sh`: build 直後に `--write` で `$BASE/dist-manifest.json`（0600、commit=HEAD）を生成する。`AIHD_DIST_MANIFEST` は staging-smoke の直前まで env に載せない。
- `scripts/staging-smoke.mjs`: 起動前に manifest の path（絶対・正規化・制御文字なし）・種別（regular / non-symlink）・owner（実行 user）・mode 0600・size を検証する。続いて manifest.commit と `git rev-parse HEAD` の一致、dist 全ファイルの hash 一致を確認し、`COMMIT_SHA` には manifest.commit を使う。dist guard の import は manifest 検証の後に行う。

### 3. dotenv 境界（M3）

- `apps/api/src/config.ts`: dotenv 呼出前に `initialNodeEnv` を捕捉し、モード判定（production / test / 検証用フラグ）を初期値に固定する。dotenv 後に `initialNodeEnv !== 'test'` かつ `process.env.NODE_ENV === 'test'` なら固定文言で exit 1（env ファイルで test を名乗れない）。
- `scripts/migrate.ts` / `scripts/seed.ts`: 自入口の dotenv 呼出前にも `initialNodeEnv` を捕捉し、モード判定を初期値に固定する。ただし seed は import 経由で `config.ts` が先に評価され得るため、seed の `initialNodeEnv` が常に dotenv 前とは限らない。その場合も `config.ts` の `isEnvFileTestSwitch` が test 切替を exit 1 で拒否するため fail-closed で、seed 本体の判定には到達しない。
- `apps/api/src/lib/test-database.ts`: 純粋関数 `isEnvFileTestSwitch(initial, current)` を追加。
- migrate / seed のエラー redaction は `isTest` だけでなく `testDatabase` が定義された場合にも適用する。ただし test 切替はその直前に exit 1 するため、この分岐は主経路では到達しない **defense-in-depth**（多層防御）であり、追加の検出効果を主張しない。

## 限界

- `staging-smoke` は read-only ではない。起動時の catalog 同期が skills を upsert するため、承認状態・日時が変わり得る。新規の専用合成 DB 以外では実行しない。
- 隔離は `verify-isolated.sh` が新規 PG16 クラスタを作る経路が前提。既存 DB 名の使い回し、通常 checkout、稼働中配置・本番配置での実行を安全とはみなさない。
- dist manifest は署名のない自己生成 JSON である。build 直後に書いた場合だけ「その時の dist」と HEAD を束縛する。誰でも再生成・差し替えができ、正規 commit・署名付き artifact・配信 bytes の証明ではない。
- 所有証明が示すのは「新規 DB の comment に刻印した token を smoke が起動前に読めた」ことだけ。他プロセスの同時接続や DB への書き込み不存在を証明しない。
- dotenv 境界の修正は、env ファイルで test を名乗る経路を閉じるもの。プロセス環境に test を明示した場合の運用 DB への誤接続を防ぐのは `assertTestDatabase`（loopback・許可 DB 名・完全一致）で、その前提は `verify-isolated` の新規クラスタ作成である。
- 実 Cloudflare Access / OTP、実社員・貸与 PC・別人物承認、正式 Staging・本番配備の受入ではない。
