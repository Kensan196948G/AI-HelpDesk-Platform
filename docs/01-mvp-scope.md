# MVP スコープ・受入条件（v1.0 / 承認待ち）

> **2026-10-23 ユーザー指示による変更**: WebUI は既存プロトタイプ HTML を 100% 適用し、
> Cloudflare Access（OTP / 12h / 指定メールのみ）を唯一のログインとし、自由記述の AI 回答に
> DeepSeek API を使う。実装は [14-prototype-ui-integration.md](14-prototype-ui-integration.md) を正本とする。

## 1. Goal → User → Problem → Value

| 項目 | 内容 |
|---|---|
| Goal | 社員の IT 相談を 1 つの入口で受け、AI 一次対応からヘルプデスク対応、ナレッジ化までを一気通貫で体験できる個人利用 MVP を作る |
| User | 検証者 1 名。相談者・ヘルプデスク担当・承認者の 3 ロールをデモアカウントで切替 |
| Problem | 窓口がばらばら／同じ質問のくり返し／PC 情報を聞き出す手間／解決知見が属人化／対応記録が残らない |
| Value | 相談受付の標準化、PC 基本情報の事前取得による聞き直し削減、根拠付き一次回答、引継ぎ・解決記録・ナレッジ化の一本化 |

## 2. 主要 3 Flow

### Flow A: 相談受付〜引継ぎ（STEP 1〜4）
1. 相談者がログインし「新しい相談」を開始。
2. 6 種類から相談種類を選択（例文・既定の PC 取得可否）。
3. 件名・内容・急ぎを入力。PC 基本情報（8 分類 31 項目）のデモ取得を開始し、進捗と気になる点を表示。
4. 「AI に相談する」で、ルールベース一次対応（意図判定＋承認済みナレッジ検索）を実行。
   - 承認済みナレッジが見つかれば、根拠・確認事項・対処手順を提示。
   - セキュリティ相談は赤信号。AI は初動手順のみ提示し、担当者へ。
5. 「解決した」→ STEP 7 完了（チケットなし）。
6. 「解決しない」→ STEP 4 引継ぎ。渡す情報を選択し同意 → TKT / INC 番号を発行し、STEP 5 へ。

### Flow B: ヘルプデスク対応（STEP 5）
1. 担当者がボード／一覧で引継ぎ待ちを確認。
2. 案件詳細で引継ぎメモ、AI 経過、共有された PC 基本情報を確認。
3. 自分を担当者に割当 → 対応中へ。
4. 解決記録（原因・手順・所要時間）を登録 → 案件は STEP 6 へ。
5. 相談者の案件詳細に、担当者・状態・解決内容が反映される。

### Flow C: ナレッジ化〜完了（STEP 6〜7）
1. 解決記録から、伏せ字済みのナレッジ下書きを自動生成。
2. 担当者が内容を整え、承認申請（下書き → 承認待ち）。
3. 申請者とは別の承認者が 4 項目チェックリストで承認（差戻しは理由必須）。
4. 承認と同時に公開。案件は STEP 7 完了。
5. 公開ナレッジは、次の相談の AI 一次対応の根拠として使われる。
6. 相談者の画面に、解決とナレッジ公開が反映される。

## 3. 画面（MVP）

| # | 画面 | ルート | 主な利用者 | 主な状態 |
|---|---|---|---|---|
| S1 | ログイン | `/login` | 全員 | 通常 / 入力エラー / 認証エラー / 送信中 |
| S2 | ホーム | `/` | 全員 | 通常（相談者 / 担当者）/ 空 / 取得エラー |
| S3 | 相談ウィザード STEP 1〜4 | `/consult/new` | 相談者 | 通常 / 入力エラー / PC 取得中 / AI 回答 / 赤信号 / 引継ぎ完了 |
| S4 | 相談の状況 | `/cases/:id` | 相談者 | 通常 / 空 / 読込中 / エラー |
| S5 | ヘルプデスク ボード／一覧 | `/desk` | 担当者・承認者 | 通常 / 空 / 自分の番 / 読込中 |
| S6 | 案件対応 | `/desk/cases/:id` | 担当者・承認者 | 通常 / 担当未定 / 解決記録入力エラー / 完了 |
| S7 | ナレッジ | `/knowledge`, `/knowledge/:id` | 担当者・承認者 | 通常 / 承認待ち / 空 / 差戻し / 自分の申請（承認不可） |
| S8 | 監査ログ | `/audit` | 承認者 | 通常 / 改ざん検知 / 空 |

補足: 404、通信エラー、トースト、ローディングスケルトンを含む。SP は簡易対応（サイドバーを下部ナビ化）。

## 4. ロールと権限

| ロール | できること | できないこと |
|---|---|---|
| 相談者 `requester` | 自分の相談の作成・閲覧、引継ぎ同意、PC 情報の閲覧 | 他人の相談、担当者操作、ナレッジ承認 |
| ヘルプデスク `helpdesk` | 全案件の閲覧、担当割当、解決記録、ナレッジ下書き・申請 | ナレッジ承認（自分の申請は不可）、監査ログの閲覧は不可 |
| 承認者 `approver` | ナレッジ承認・差戻し、監査ログ、全案件の閲覧 | 解決記録の登録、自分の申請の承認 |

- 認証: メール＋パスワード（Seed で 3 アカウント）。HttpOnly セッション Cookie。
- 認可: **API サーバ側**でロールと所有者を検証。UI の非表示だけに頼らない。
- 本番想定の SSO / Entra ID / Cloudflare Access は MVP 対象外（Backlog）。

## 5. データ（Local PostgreSQL）

| テーブル | 役割 |
|---|---|
| `users` | 3 ロールのデモ利用者 |
| `sessions` | セッショントークン（ハッシュ保存） |
| `cases` | 相談案件（番号・種類・件名・本文・急ぎ・信号・STEP・状態） |
| `case_messages` | AI 一次対応・相談チャットの記録 |
| `pc_snapshots` | PC 基本情報 31 項目（デモ）・気になる点・共有可否 |
| `tickets` | TKT / INC 番号、担当、引継ぎメモ、共有項目 |
| `resolutions` | 原因・手順・所要時間 |
| `knowledge` | 下書き・承認待ち・公開・差戻し、版 |
| `knowledge_reviews` | 承認/差戻し、チェックリスト、理由 |
| `audit_log` | ハッシュチェーン付き操作記録 |

- Migration は空 DB から再実行可能（`IF NOT EXISTS` / 冪等）。
- Seed は再実行可能（upsert）。**TRUNCATE / DROP は使わない**。
- 専用 DB `ai_helpdesk_mvp` を新規作成し、既存 DB は変更しない。

## 6. AI 一次対応（MVP の現実的な線）

- **ルールベース**で意図（印刷 / VPN / 音声 / 容量 / 共有フォルダ / ログイン / セキュリティ / 手続き / その他）を判定。
- 承認済みナレッジをキーワード検索し、根拠として提示。根拠がなければ「担当者へ」を推奨。
- 相談本文は命令ではなく**データ**として扱う（プロンプトインジェクション対策の原則を UI/実装に明記）。
- 外部 AI API には接続しない。`AiProvider` インターフェースだけ用意し、将来の差替え点を明示。
- 画面上に「MVP: DeepSeek-V4.1-Flash + 承認済みナレッジ」を表示する。

## 7. PC 基本情報（実端末・読み取りのみ）

- ログイン中のブラウザから、OS・画面・CPU コア・メモリ・GPU・回線・音声などの実機情報を取得する。
- 端末エージェント導入時は、CPU/メモリ/ディスク/GPU/ネットワーク/プリンター/音声/USB/導入ソフト/セキュリティ状態も取得する。
- 8 分類 35 項目のスナップショットを生成し、正常 / 注意 / 異常を判定。相談文との関連度（★）順に「気になる点」を表示。
- 「取得しない情報」（ファイルの中身・閲覧履歴・画面・キー入力・メール本文・個人フォルダ一覧）を明示。
- 共有は本人の同意がある場合のみ。担当者以外・未共有の案件では API が値を返さない。
- IP・シリアル・資産番号・メールは AI へ渡す前に伏せる。端末エージェントは読み取り専用。

## 8. セキュリティ・プライバシー（MVP）

- 相談本文・解決記録・ナレッジ下書きの保存前に、パスワードらしき文字列・メール・電話・IP・カード番号を伏せ字化。
- ログに個人情報・本文を出さない（リクエスト ID とメタ情報のみ）。
- Secret は `EnvironmentFile`（0600）と Cloudflare Worker Secret に置き、リポジトリへコミットしない。
- セキュリティヘッダ（CSP, X-Content-Type-Options, Referrer-Policy, frame-ancestors）を Worker で付与。
- ログイン試行のレート制限、セッション有効期限、ログアウト、Cookie の HttpOnly/SameSite。
- 監査ログは SHA-256 のハッシュチェーン。検証 API を用意。
- 既知の受容リスク: デモパスワード、Access ヘッダーの信頼、AI の幻覚、PC エージェントの配布・トークン管理。docs に明記。

- 外部 AI の運び役・指示書・費用上限・モデル試験（FR-32〜36）
- 電話・メールの代行受付（FR-28）
- 問い合わせ台帳・機器台帳・CSV 出力（FR-39, 40）
- 受け入れ試験 19 項目・AI 試験 12 問の画面（FR-42）
- SSO / Entra ID / 多要素認証（Cloudflare Access + OTP は実装済み。SSO 連携は対象外）
- desknet's NEO / AppSuite / DirectCloud / SKYSEA 連携
- 本番正式環境、Production deploy、メール通知、多言語
- 28 画面の業務ツール、ドラッグ&ドロップ、高度な版管理・差分

## 11. 仮定（要件不足時の補完）

- 利用者は 1 名。デモアカウントでロールを切替える。
- 本番の SSO・PC エージェント配布基盤・ヘルプデスク基盤は未提供のため、MVP では代替（Cloudflare Access、ブラウザ + 読み取り専用エージェント、内蔵チケット）。
- 添付・修復・代行受付は MVP の主要価値に不要なため対象外。
- 画面は PC ブラウザ中心。820px 以下は簡易的な下部ナビで閲覧可能にする。
- Seed / テストデータはデモ。実運用では Access で認証された本人の PC 情報（読み取りのみ）を保存する。
