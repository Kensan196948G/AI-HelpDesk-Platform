## 3. 発見した実欠陥と修正（正規 PR）

### 3-1. symlink 経由で `main()` が実行されない（PR #143, merge `65caaa2`）

- 症状: `ai-helpdesk-stg-proxy` が `NRestarts=10` / `ExecMainStatus=0` / `active(auto-restart)`。アプリ出力なし。
- 原因: `import.meta.url === pathToFileURL(process.argv[1]).href` は、`current` symlink 経由起動だと `import.meta.url`（実パス）と `argv[1]`（symlink パス）が一致せず偽になる。`main()` を実行せず exit 0。
- 実測（修正前）: release の `proxy-sidecar.mjs` を symlink 経由で起動 → 無出力・リスンなし・exit 0。
- 修正: `scripts/lib/is-main.mjs` で双方 realpath 解決して比較。5 スクリプトを共通化。単体試験 9 件。
- 実測（修正後）: symlink 経由で `listening on http://127.0.0.1:18993`、proxy 経由 `/api/health` 200。

### 3-2. read-only release の manifest 検証が常に失敗（PR #144, merge `46261ea`）

- `deploy-release.sh` は `chmod -R a-w` するため manifest は 0400。`readManifestFile` は 0600 固定要求 → `DIST_MANIFEST_MODE_INVALID`。
- 実測: 本番 dry-run release の manifest（mode 400）で再現。修正後 `DIST_MANIFEST_OK 29913c01…`。
- 併せて `build` 前に `dist` を掃除（本番 dist に削除済みモジュールが残る問題の再発防止）。

### 3-3. 本番配備手順が本番全断を招く（PR #142 レビュー / NO-GO）

- 独立レビューが C-1（dry-run だけでは `current` も unit も作られず、旧 unit 停止→存在しない新 unit 起動になる）、C-2（`COMMIT_SHA` の供給元が未記載）、H-1〜H-6 を指摘。
- 対応: `docs/82` を改訂中（task-3 相当）。実装側は PR #146 で `--unit-template` と restart 失敗時 rollback を追加。
- **PR #142 はまだマージしていない。**
