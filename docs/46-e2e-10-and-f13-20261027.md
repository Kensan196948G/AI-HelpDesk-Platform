## 1. E2E 10ラン（2アカウント引継ぎ・API 契約）

`scripts/e2e/two-account-handover.mjs` を 10 回連続実行した。各ランは次の一気通貫を実 DB で検証し、終了時に状態を復元する。

1. A（合成アカウント・`@mirai-const.co.jp`）が PC 情報付きの案件を DX グループへ共有
2. B（DX 推進部の実在社員・名簿から解決）の受信箱に案件が出る → **claim**
3. B の状態へスナップショットがマージされ、案件・チャットが STEP3 で開く

5. 共有スナップショットの PC 情報が **F-04 の伏せ字**（`[IPアドレス]` / `[シリアル番号]`）で保持され、生値が残らない
6. 承認を経ない `completed` は **409 APPROVAL_REQUIRED**
7. C（別の DX 担当者）の承認で `completed`・`selfApproved=false`
8. DB: `completed` / 承認者=C / 自己承認ではない
9. 実行後に状態を復元（残存 0 件）

## 2. F-13 の本番 UI 確認

本番 `https://ai-helpdesk.mirai-dx-platform.com/` で、依頼者（`有藤 健太郎`）の完了案件 **CASE-39196** を「一覧」から開いた。

| 確認 | 実測 |
|---|---|
| 完了案件の表示 | **STEP 7（完了）** が表示され、「この案件は完了しました」「担当者の解決内容: 有藤 健太郎: VPN仮想アダプタが無効…」「相談した人への通知 2件」「次にやる人: 完了」 |
| 案件カード | 受付 `TKT-2026-0005` / ヘルプデスク `INC-1009｜P4｜解決済｜担当 有藤 健太郎` / ナレッジ `DR-004（下書き）` |
| サーバ状態との一致 | `case_handovers`: `status=completed` / `approved_by=k-aritoh@mirai-const.co.jp` / `self_approved=false` |

- **判定: F-13 の核（completed → STEP7 への反映）は本番 UI で確認**。
- ただし **承認者名・承認日時は STEP7 画面に表示されない**。F-13 の実装では承認情報は同期時の**トースト/チャット通知**（`DX推進部の対応が完了しました（承認: …）`）で伝える設計で、今回の再読込では状態が既に同期済みのため通知は再発火せず、承認情報の表示を画面から確認できなかった。
  - 未確認として記録する。必要なら「STEP7 に承認者・承認日時を常設表示する」改善を別途行う（現状は仕様どおり）。
