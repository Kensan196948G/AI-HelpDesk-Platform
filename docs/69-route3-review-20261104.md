# 69. 経路③の精読レビュー（2026-11-04、commit `a5e0a67`）

経路③（本人権限ヘルパーによる、本人同意付きのフォルダ一覧と共通支援セッション）を、有効にする前に精読した結果。
#130 の独立レビューで「③のサービス層、ルート、PowerShell を精読していない」とした残課題（docs/68 §8）に対応する。

- **方法:** 実装を担当していない 2 つのレビュー（サーバ側、Windows 側）が、読み取り専用で精読した。実行による確認はしていない。Windows API の挙動は、コードと仕様からの推定である。
- **結論:** critical と high は 0 件。範囲外の一覧や、同意の無い実行を再現できる経路は見つからなかった。**下の medium をすべて直すまで、③を本番で有効にしない**（2026-11-04 時点で S1、S2、S3 の一部を修正済み）（docs/68 §1 の R3 は No-Go のまま）。
- **本番の状態:** ③は無効（`FOLDER_ACCESS_ENABLED=false`、`ASSIST_SESSION_MODE=off`）。無効のときの入口は、すべて 404 を返す（`route-inventory.integration.test.ts`）。

## 1. 問題なしと確かめた点（抜粋）

- **nonce:** Y の nonce と `/start` の nonce は、どちらも条件付き UPDATE と行ロックで 1 回限り。
- **承認と同意:** 承認ハッシュは毎回いまの値から組み立て直す。操作範囲の同意は、正本の ID、版、scope、期限で照合する。承認済み Skill は manifest とハッシュで再照合する。
- **ロック:** ロックの順序は一貫している。重複報告は受け付けた時刻で止める。
- **遅れた結果:** 遅れて届いた結果は保存するが、証拠にせず次へ進めない。
- **登録:** 登録には導入コードが必須（60 ビット、1 回限り、失敗回数の制限あり）。
- **判定:** 本人と担当者の判定、提案とセッション、操作とヘルパーの対応に漏れは無い。
- **露出:** AI へ渡すのは固定の語彙、数値、ナレッジ ID だけ。監査の SID は HMAC のみ。
- **Windows 側のパス検証:**
  - 列挙はハンドルを保持したまま行い、最終パスで範囲を判定し、列挙の前後で同じ検査をやり直す。
  - `..`、デバイス名、末尾の点と空白、名前サロゲートの再解析点を拒否する。
  - ファイルの内容を読まず、ハッシュもしない。`Invoke-Expression` も文字列からのコマンド組み立ても無い。
  - 署名は他の検査より先に検証し、固定時間で比較する。
