# 社員名簿の取り込み（ヘルプデスク担当・一般社員のプルダウン）

| 項目 | 値 |
|---|---|
| 版 | v1.0 |
| 日付 | 2026-10-23 |
| 取得元 | Mirai-Info `mirai_info.employee_directory`（DeskNets 社員マスタ app_id=33） |
| 決定 | 読み取り専用DB（B）／メモリのみ／値は**社員番号（MK…）**／配置は「指名」＋「代行受付」 |

## 1. データ

| 項目 | 実測 |
|---|---|
| 全社員（`status='有効'`） | **445名** |
| DX推進部（`section='DX推進部'`） | **5名** |
| 最終更新 | 2026-10-23 08:35（当日の cron） |
| 返す項目 | 社員番号 / 氏名 / 組織 / 本部・支店 / 部署 |
| 返さない項目 | メールアドレス・カナ（PII 最小化） |

## 2. 取得方法（読み取り専用）

- ローカル PostgreSQL の **Unix ソケット + OS ユーザー（peer）** で接続。パスワードは保持しない。
- 接続直後に **`SET default_transaction_read_only = on`** を実行し、同一セッションの書き込みを拒否する。
- `MIRAI_INFO_DATABASE_URL` を設定すれば別の接続先（読み取り専用ロール）に切り替え可能。
- 名簿は **10分メモリキャッシュ**。AI HelpDesk の DB には保存しない。
- DB へ接続できない場合は空配列を返し、画面は従来のデモ名簿で動作する。

※ 本番の hardening: OS ユーザー（peer）ではなく、`employee_directory` の SELECT のみを持つ専用ロールへ移行する。

## 3. API

`GET /api/employees?scope=staff|all`（画面認証必須・60回/分）

```json
{
  "ok": true,
  "scope": "staff",
  "employees": [{ "employeeNo": "MK1073", "name": "…", "organization": "…", "division": "管理本部", "section": "DX推進部" }],
  "total": 5,
  "cachedAt": "2026-10-23T11:40:00.000Z",
  "source": "mirai-info.employee_directory"
}
```

## 4. 画面

| 画面 | 変更 |
|---|---|
| 引継ぎの「担当（指名）」 | DX推進部5名のプルダウン。値は**社員番号**、表示は「本部 / 部署 / 氏名」 |
| 代行受付（電話・メール）の「依頼者」 | 全社員445名のプルダウン。値は**社員番号**、表示は「本部 / 部署 / 氏名」 |

- ヘルプデスク（INC）の担当表示は**氏名**（`assigneeLabel`）を使い、チケットには社員番号も保持する。
- 代行受付のチケットは `requester`（表示名）と `requesterNo`（社員番号）を保持する。
- 名簿が取得できない場合は、従来のデモ担当者リスト／「名簿を読み込み中」にフォールバックする。

## 5. PII の扱い

- `employee_directory` は平文 PII（氏名・社員番号・メール）。Mirai-Info では Access ゲート付き 18083 のみ配信。
- AI HelpDesk 側は **メールを取得・保存しない**。氏名・部署・社員番号のみをメモリに保持。
- 画面は Cloudflare Access + アプリ許可リストで保護された認証済み利用者のみ。
- 社員番号を値にする決定（2026-10-23）に従い、チケットに保存する。保存範囲は最小限。

## 7. 制限

- デモのサンプル入力は依頼者を自動選択しない（プルダウンから選択が必要）。
- 名簿の更新は Mirai-Info の cron（平日 8:35 / Entra 6時間毎）に依存。AI HelpDesk 側は10分キャッシュ。
- 所属の判定は `section`（部署）を使用。`org_units` の複合名は使わない。
