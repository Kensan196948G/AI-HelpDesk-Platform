| 項目 | 値 |
|---|---|
| 版 | v1.0 |
| 日付 | 2026-10-23 |
| 取得元 | Mirai-Info `mirai_info.employee_directory`（DeskNets 社員マスタ app_id=33） |
| 決定 | 読み取り専用DB（B）／メモリのみ／値は**社員番号（MK…）**／配置は「指名」＋「代行受付」 |

## 1. データ

| 項目 | 実測 |
|---|---|
| 全社員（`status='有効'`） | **445名** |
| DX推進部（`section='DX推進部'`） | **5名** |
| 最終更新 | 2026-10-23 08:35（当日の cron） |
| 返す項目 | 社員番号 / 氏名 / 組織 / 本部・支店 / 部署 |
| 返さない項目 | メールアドレス・カナ（PII 最小化） |

## 2. 取得方法（読み取り専用）

- ローカル PostgreSQL の **Unix ソケット + OS ユーザー（peer）** で接続。パスワードは保持しない。
- 接続直後に **`SET default_transaction_read_only = on`** を実行し、同一セッションの書き込みを拒否する。
- `MIRAI_INFO_DATABASE_URL` を設定すれば別の接続先（読み取り専用ロール）に切り替え可能。
- 名簿は **10分メモリキャッシュ**。AI HelpDesk の DB には保存しない。
- DB へ接続できない場合は空配列を返し、画面は従来のデモ名簿で動作する。

※ 本番の hardening: OS ユーザー（peer）ではなく、`employee_directory` の SELECT のみを持つ専用ロールへ移行する。

## 3. API

`GET /api/employees?scope=staff|all`（画面認証必須・60回/分）

```json
{
  "ok": true,
  "scope": "staff",
  "employees": [{ "employeeNo": "MK1073", "name": "…", "organization": "…", "division": "管理本部", "section": "DX推進部" }],
  "total": 5,
  "cachedAt": "2026-10-23T11:40:00.000Z",
  "source": "mirai-info.employee_directory"
}
```

## 4. 画面

| 画面 | 変更 |
|---|---|
| 引継ぎの「担当（指名）」 | DX推進部5名のプルダウン。値は**社員番号**、表示は「部署 / 氏名」（本部段は省略） |
| 代行受付（電話・メール）の「依頼者」 | 全社員445名のプルダウン。値は**社員番号**、表示は「部署 / 氏名」（本部段は省略） |

- 表示名は **「部署 / 氏名」**。`division` が「〜本部」で `section` がある場合は `division` を省く（例: `管理本部 + DX推進部` → **DX推進部 / 佐藤 奨太**、`技術本部 + 技術部` → **技術部 / 亀井 泰裕**）。支店は残す（例: **中部支店 / 工事部 / 上田 志途**）。2026-10-23 決定。

- ヘルプデスク（INC）の担当表示は**氏名**（`assigneeLabel`）を使い、チケットには社員番号も保持する。
- 代行受付のチケットは `requester`（表示名）と `requesterNo`（社員番号）を保持する。
- 名簿が取得できない場合は、従来のデモ担当者リスト／「名簿を読み込み中」にフォールバックする。

## 5. PII の扱い

- `employee_directory` は平文 PII（氏名・社員番号・メール）。Mirai-Info では Access ゲート付き 18083 のみ配信。
- AI HelpDesk 側は **メールを取得・保存しない**。氏名・部署・社員番号のみをメモリに保持。
- 画面は Cloudflare Access + アプリ許可リストで保護された認証済み利用者のみ。
- 社員番号を値にする決定（2026-10-23）に従い、チケットに保存する。保存範囲は最小限。

## 7. 制限

- デモのサンプル入力は依頼者を自動選択しない（プルダウンから選択が必要）。
- 名簿の更新は Mirai-Info の cron（平日 8:35 / Entra 6時間毎）に依存。AI HelpDesk 側は10分キャッシュ。
- 所属の判定は `section`（部署）を使用。`org_units` の複合名は使わない。

## 8. ヘッダー「操作する人」のロール分け（2026-10-23 追加）

ヘッダー右上の「操作する人」を、デモ名簿ではなく Mirai-Info の実名簿から選べるようにした。

| ロール（表示） | 対象 | 人数（実測） |
|---|---|---|
| 一般社員 | **全社員** | 445 |
| ヘルプデスク担当 | **DX推進部 メンバー全員** | 5 |
| ナレッジ承認者 | **DX推進部 メンバー全員** | 5 |
| 監査担当者 | **DX推進部 メンバー全員** | 5 |
| IT端末管理者 | DX推進部 メンバー全員（**追加**） | 5 |

- **IT端末管理者を追加した理由**: L4（設定変更）の承認と緊急停止の解除は `itadmin` の権限で動く。指定の4ロールだけにすると、実名に切り替えたときに L4 の承認経路が無くなるため、同じ DX推進部 のメンバーを充てた（2026-10-23 オーナー承認済み）。
- 値は **`emp:<ロール>:<社員番号>`**。保存するのは `S.ui.real = { employeeNo, role }` だけで、**氏名は保存しない**（再読み込み時に名簿から引き直す）。
- 実名の選択者には端末 **`MRK-<社員番号>`** を自動作成する（診断・修復・提案の流れをそのまま使えるようにするため）。
- 資料（ナレッジ）の閲覧範囲は所属から決める。

| 所属（`division` / `section`） | 閲覧範囲 |
|---|---|
| DX推進部・情報システム | 全社＋管理本部＋IT |
| 経理部・財務 | 全社＋管理本部＋経理部限定 |
| 営業部・営業企画部 | 全社＋営業部門 |
| 工事部・施工本部・技術本部 | 全社＋施工部門 |
| リスク統括部・監査 | 全社＋管理本部＋監査 |
| 管理本部（総務・人事・管理部など） | 全社＋管理本部 |
| 上記以外 | 全社 |

- ヘルプデスク側の操作者（`#actor`）にも実名を登録し、ロールに応じて承認（`approver`）・監査（`audit`）の権限を付ける。
- 名簿が取得できないときは従来のデモ名簿。保存済みの選択が名簿に無いときは「（現在の選択）」として1件だけ表示する。

### 検索（補完つき・2026-10-23 追加）

- 「操作する人」の横の検索ボックスに **氏名・社員番号・部署・ロール名** を入力すると、候補（最大20件）をその場に表示する。空白区切りで絞り込みを重ねられる（例: `佐藤 DX`）。
- 候補は **ロール単位**。DX推進部の人は同じ氏名で「ヘルプデスク担当／ナレッジ承認者／監査担当者／IT端末管理者」の4件が並び、右側にロール名のチップを表示する。
- 選ぶとプルダウンと同じ経路（`applyPersonaValue`）で切り替わる。`↑` `↓` で移動、`Enter` で決定、`Esc` で閉じる。候補が無いときは「該当する社員はいません」。
- 名簿が取得できないときはデモ名簿を検索対象にする。
