# 93. 右詳細パネルのタブ化（PR-1）— 既存の引継ぎワークスペースへの取り込み（2026-11-11）

## 0. 結論

[docs/92](92-webui-flow-sample-adoption.md) §3-3 の **PR-1（右詳細パネルの骨格＋読み取り専用データ）** を、**既存の引継ぎワークスペース右ペインのタブ化**として実装した。

- 右ペインを 1 ページに並べ直し、**案件 / 実行 / 端末 / ナレッジ / 記録** の 5 タブにした。
- **新しい画面は追加しない**。原本 HTML（`Mirai_AIHelpdesk_Cowork_StepWizard_V3.1_PCinfo_Offline.html`）は変更しない。変更は `apps/api/src/prototype/handover-workspace-bridge.js` と追加テストだけ。
- データの取得・更新は変えない（**読み取り専用**。新しい API 呼び出しを足していない）。

## 1. docs/92 の計画からの変更（重要）

| 項目 | docs/92 §3-1 / §3-3 の計画 | 実装 | 理由（実測） |
|---|---|---|---|
| 追加の形 | 右詳細パネルを**新画面として追加**（担当者向け） | 既存の引継ぎワークスペース**右ペインのタブ化** | 仕様書 V1.0 の右詳細パネル（SC-06 相当）の情報項目は、既存の右ペインのカード（案件情報・RSP実行・端末共有・AI承認・ナレッジ・下書き・記録・開く）と重複していた。新画面にすると同じ情報を 2 画面で持つことになり、docs/92 §3-1 #1 の「役割重複を整理」に反する |
| 原本 HTML | 変更しない | 変更しない | 同じ |

docs/92 §3-1 #1 の条件「原本 HTML は変更しない」は満たしている。新画面の追加ではなく既存ペインの再編なので、**画面遷移は増えていない**。

## 2. 変更内容

### 2-1. タブと中身

| タブ | パネルの中身 | 件数バッジ |
|---|---|---|
| 案件（既定） | 案件情報（案件・状態・優先度・受付・期限・担当・分野）、開く（既存の画面で開く／利用者の受付番号） | なし（状態はカード側に出す） |
| 実行 | RSP実行セッション（既存の `tcHTML`）、AI操作の承認記録（提案があるときだけ） | なし |
| 端末 | 端末・共有情報（本人同意のチップ付き） | 共有項目数 |
| ナレッジ | 関連ナレッジ、ナレッジ下書き | 関連ナレッジ数＋下書きの有無 |
| 記録 | 操作の記録（監査ログ） | 実際に表示する最新 6 件まで |

- バッジは**そのパネルに実際に出す件数**だけを数える。パネルの中身と件数を食い違わせない（実行・案件はバッジを出さない）。
- 監査ログは従来どおり**最新 6 件**だけを表示する（全件表示は PR-3 以降の課題）。

### 2-2. 操作と状態

- タブの切り替えは `hidden` の付け替えだけで、**右ペインを再描画しない**。入力中の値・フォーカス・スクロールを失わない。
- タブごとのスクロール位置を保持する（`HW.evScroll`）。案件を切り替えたときは先頭に戻す。
- 全体の再描画（`renderAll` / `renderEv`）でも、選択中のタブを保つ（`HW.evTab`）。
- 既定は「案件」。
- WAI-ARIA の tabs パターン: `role="tablist" / "tab" / "tabpanel"`、`aria-selected`、`aria-controls`、`aria-labelledby`、選択していないタブは `tabindex="-1"`。左右キー・Home/End で移動できる。
- 幅 1120px 以下で右ペインを隠す既存の挙動は変えていない（タブも一緒に隠れる）。

## 3. 読み取り専用データであること

- 追加した取得はない。既存の `tickets()` / `cowork()` / `auditList()` / `kbList()` / `draftList()` / `relatedKbs()` をそのまま使う。
- RSP 実行セッションの取得（`tcLoad`）も従来のまま。API が無い環境では従来どおり「通信に失敗しました」と表示する。
- 「開く」「下書きを開く」などは既存の処理を呼ぶだけで、業務ロジックを二重実装していない。

## 4. 検証

### 4-1. 自動試験

| 試験 | 結果 |
|---|---|
| `npm run typecheck` | 成功 |
| `biome check`（変更 2 ファイル、エラー） | 成功（警告は既存分） |
| prototype の単体試験（`apps/api/src/prototype/*.test.ts`） | 8 ファイル / 154 件 成功（新規 10 件を含む） |

新規試験の内容:

- タブは 5 つで、順序とラベルが 案件→実行→端末→ナレッジ→記録 である。
- 既定は「案件」で、再描画しても選択を失わない。
- 5 つのパネルをすべて組み立てる。
- ARIA（tablist / tab / tabpanel / aria-selected / aria-controls / aria-labelledby）。
- キーボード移動と、`hidden` の切り替えだけで入力値を消さないこと。
- バッジの件数（端末＝共有項目数、ナレッジ＝KB＋下書き、記録＝最新 6 件まで、案件・実行は 0）。

### 4-2. UI スモーク（スクリーンショット）

原本 HTML にブリッジを差し込んだ**スタンドアロンのハーネス**（API・DB・認証なし）で、ブラウザ（Playwright）により実操作した。データは件名に「（UIスモーク）」と明記した検証用データだけを使い、デモ案件は表示していない。

| 画像 | 内容 |
|---|---|
| `docs/evidence/handover-tabs/00-workspace.png` | ワークスペース全体（右ペインのタブ） |
| `01-case.png` 〜 `05-record.png` | 各タブ（案件・実行・端末・ナレッジ・記録） |

実測したこと:

- タブは 5 つ。初期状態は「案件」が `aria-selected="true"`、他の 4 つは `false` / `tabindex="-1"`。
- タブをクリックすると `aria-selected` と表示パネルが 1 つだけ切り替わる。
- 右ペインに試験用の入力要素を足してタブを往復しても、**同じ DOM ノードと値が残る**（再描画していない）。
- `window` の `focus` による**全体再描画の後も、選択中のタブが保たれる**。
- フォーカスを「案件」に置いて `ArrowRight` を押すと「実行」が選択され、フォーカスも移る。
- 端末タブのバッジは 4（共有 4 項目）、ナレッジは 3（KB 2 件＋下書き 1 件）、記録は 3（監査 3 件）で、表示内容と一致した。

**限界（未検証）**: 実サーバ（API・DB・Cloudflare Access）での操作は未実施。ハーネスでは受信箱 API が無いため、左ペインに「受信箱を取得できませんでした」と出る（ハーネス由来で、画面の不具合ではない）。スクリーンショットの「通信に失敗しました」（実行タブ）も同じ理由である。
