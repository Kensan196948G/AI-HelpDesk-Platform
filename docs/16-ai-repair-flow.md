# AI修復フロー仕様（ヒアリング → 確認 → Y/N → 実行 → 結果）

| 項目 | 値 |
|---|---|
| 版 | v1.0 |
| 決定日 | 2026-10-23 |
| 対象 | 相談ウィザードの AI 相談（`#cw`）と操作許可リスト（OPS） |
| 前提 | PC基本情報の事前取得が完了していること |

## 1. 目的

PC基本情報の取得後、**ヒアリング → 入力確認 → 読み取り確認 → 対応案 → 本人Y/N → 実行 → 結果 → 次の一手**を、端末を壊さず・記録を残して回す。

## 2. 決定事項

| 論点 | 決定 |
|---|---|
| Y/N の主体 | **本人**（相談員による代理承認は行わない） |
| 再起動 | 許可リストに `REBOOT` を追加（Lv3）。**本人のY**で実行 |
| 1相談あたりの上限 | **15コマンド**。超過時は自動実行せず担当者へ引継ぎ |
| N を選んだ場合 | **引継ぎ要約を自動生成**して担当者へ |
| 引継ぎ先 | **特定の相談員を指名**（社員マスタから選択） |

## 3. フロー（状態）

| # | 主体 | アクション | ガード・記録 |
|---|---|---|---|
| S0 | 端末 | PC基本情報を取得（読み取りのみ） | 変更しない。取得日時・項目数 |
| S1 | 相談員 | ヒアリング入力（症状・いつから・対象・試したこと・影響） | PII は伏字。AIへは必要最小限 |
| S2 | AI | 復唱＋不足確認（「この内容で合っていますか？」Y/N） | N なら S1 へ |
| S3 | AI/端末 | 読み取り確認（診断コマンド） | 読み取りのみ。結果を提示 |
| S4 | AI | 対応案の提示（OPSから選択。対象・影響・戻し方・Lv）＋実行Y/N | 許可リスト外は提案不可 |
| S5 | **本人** | Y / N | Y→S6、N→S8（引継ぎ要約） |
| S6 | サーバー | 実行前検証（承認ハッシュ・停止・権限・L4・自己承認）→ 実行 | 不合格なら実行しない |
| S7 | AI | 結果報告（成功/失敗・検証値）＋次のコマンド／再起動のY/N | 失敗時は「変更なし」を明示 |
| S8 | 本人/相談員 | OK（解決）／ダメ（引継ぎ） | 解決記録 or チケット（指名） |
| S9 | システム | 監査・ナレッジ化 | ハッシュチェーンで記録 |

補足:
- **入力確認は2段階**に分ける。文章の復唱（S2）と、読み取り確認コマンド（S3）。
- **1コマンドずつ**。複数必要なら結果を見てから次の Y/N。
- **再起動は独立したY/N**。再起動後の再取得・確認までを1セットにする。
- **15コマンド**に達したら、それ以上は提案せず引継ぎ要約を出す。

## 4. 実装との対応（プロトタイプ）

| 要素 | 実装 |
|---|---|
| 許可リスト | `OPS`（Lv0〜4。Lv5 は提案自体を作らずブロック） |
| 承認 | `createProposal` → `userDecision`（本人のみ） |
| 実行前検証 | `serverVerify`（承認ハッシュ・緊急停止・Lv4・自己承認・端末一致） |
| 実行 | `applyOp`（模擬。成功時は検証値を返す） |
| 元に戻す | `rollbackOp`（`rollbackable` の操作のみ） |
| 再起動 | `OPS.REBOOT`（Lv3）と `applyOp` の `REBOOT` ケース（模擬） |
| 連鎖 | `OP_NEXT`（現状: `TEMP_CLEAN_USER` → `REBOOT`） |
| 上限 | `MAX_OPS_PER_CHAT = 15`。`prop()` と実行後の連鎖で判定 |
| N の要約 | `ACT.N` が理由付きの引継ぎカードを自動生成 |
| 指名 | 引継ぎカードの「担当（指名）」→ `createTicket.assignee` → `HD.intake` の `assignee` |

## 5. ガードレール

- AI はコマンドを自由生成しない。**OPS の許可リストから選ぶ**。
- 承認は**内容と結びつく**（承認後に内容が変われば実行しない）。
- Lv4 は**本人Y＋IT管理者承認**。自己承認は拒否。
- 緊急停止中は実行しない。実行中も中断できる。
- 失敗時は**端末を変更しない**。証跡（検証項目）を付けて引継ぎ。
- 監査に「依頼者・承認者・実行端末・操作・結果」を残す。

## 6. 検証（2026-10-23 実測）

headless ブラウザで以下を確認した。

| 確認 | 結果 |
|---|---|
| `TEMP_CLEAN_USER` 実行 → 続けて `REBOOT` の Y/N が出る | ✅ 連鎖メッセージと提案カード |
| `REBOOT` に Y → 実行（模擬）と検証値（再起動・再取得・未保存の作業） | ✅ `status: done` |
| N → 引継ぎカードに理由（提案名・Lv・対象・変更なし）が出る | ✅ |
| 引継ぎカードの「担当（指名）」→ チケットとヘルプデスク（INC）の担当に反映 | ✅ 田中 → 鈴木 に変更して一致 |
| 15コマンド到達後は提案を作らず引継ぎカードを出す | ✅ `used: 17 / created: false / consent: true` |
