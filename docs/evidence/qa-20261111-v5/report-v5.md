### 6-2. #5 の限界（重要）

- STEP4 の同意送信後、UI は「引き継ぎました（TKT-2026-0001／INC-1008）」と表示したが、**サーバーの受信箱（`GET /api/case-handovers/inbox`）は 0 件のまま**で、`POST /api/case-handovers` も発行されなかった。
- 原因はローカル環境に **Mirai-Info の社員名簿が無い**こと。引き継ぎの共有は assist-bridge が「宛先（社員）を解決できた場合」に実行するため、名簿が無いと UI 内の記録だけで止まる（`/api/me` の `employee` も null）。
- したがって **相談者 → 担当者のサーバー経由の引き継ぎ（STEP4 のサーバー反映）は、ローカルでは未検証**である。API 経路自体は CI の integration test で検証されているが、この受入では実測していない。
- Staging / 本番（Access OTP）では名簿が利用できるため、そこで STEP5〜7（引き受け・解決記録・承認）まで含めた通し確認が必要である（[docs/96](../../96-release-prep-webui-20261111.md) §5 の V-3〜V-6）。

### 6-3. 環境操作の記録

- 引継ぎワークスペースの表示には「DX 推進部の担当者」の権限が要るため、画面の操作者を `emp:staff:MK1073`（DX推進部 / 佐藤 奨太）に切り替えて確認した（プロトタイプの操作者選択。サーバーの認証主体は `DEV_AUTH_EMAIL` のまま）。
