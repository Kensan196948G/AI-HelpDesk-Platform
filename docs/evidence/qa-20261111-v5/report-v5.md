# UI 受入 再実行レポート v5（2026-11-11）

## 0. 結論

PR-1（[docs/93](../../93-right-panel-tabs.md)）・PR-2（[docs/94](../../94-knowledge-trial-and-review.md)）・PR-3（[docs/95](../../95-right-panel-footer-and-reflect.md)）の WebUI 変更後に、UI 受入の **A05（Normal State）** と **A08a（Input Error）** を再実行した。**両方 PASS**。

- 対象は、サーバーが組み立てて配信するページ（原本 HTML ＋ 配信時の差し替え ＋ ブリッジ 11 本）。ハーネスではなく実サーバーの応答。
- 環境は**ローカル開発サーバー**。本番・Staging・Cloudflare Access は使っていない（§4）。

## 1. 環境

| 項目 | 内容 |
|---|---|
| サーバー | `apps/api/src/index.ts` をローカルで起動（`127.0.0.1:18972`） |
| モード | `NODE_ENV=development`、`AUTH_MODE=local`（`DEV_AUTH_EMAIL` のローカル認証）、`COOKIE_SECURE=false` |
| DB | ローカルの開発 DB（`ai_helpdesk_mvp`、migration 適用済み）。書込みなし（§3） |
| ブラウザ | Playwright の Firefox（1280×720） |
| 起動方法 | ローカルの設定ファイルは変更せず、子プロセスの環境だけポートを差し替えた（`/tmp` の一時 preload。リポジトリには含めない） |
| 配信内容 | 原本 HTML は不変。ブリッジは PR-1〜3 の 3 本を含む |

補足: 起動時にサーバーが `window.__AIHD_BOOT__` で保存状態を渡すため、画面は前回の相談（CASE-0001）の STEP 2 から開いた。これは既存の状態復元の挙動で、今回の変更によるものではない（原本 HTML 単体を直接開いた場合は STEP 1 から開くことを別途確認した）。

## 2. 結果

| ケース | 確認内容 | 実測 | 判定 |
|---|---|---|---|
| A05 Normal State | `/` が 200、title が「みらいAI窓口 × ヘルプデスク ステップ受付 V3.1」、本文サイズ、相談ウィザード（STEP 1〜7）の表示、ページの JS エラー 0、スクリーンショット | **200** / title 一致 / 本文 **821 KB**（innerHTML） / ステップバー STEP 1〜7 と相談画面を表示 / `pageerror` **0** / スクショ取得 | **PASS** |
| A08a Input Error | 相談ウィザード STEP 2 で件名・本文を空のまま「AIに相談する」→ トースト「内容を入力してください」、STEP 2 に留まる、`POST /api/cases` なし、ページの JS エラー 0 | トースト **「内容を入力してください」**（`#toast`） / **STEP 2 のまま** / API 呼び出し **0 件**（下記） / `pageerror` **0** | **PASS** |

- 本文サイズは v4 の 670 KB から 821 KB に増えた。PR-1〜3 のブリッジ 3 本（タブ・検査・反映）と、サーバーが注入する保存状態の差による。表示・操作に影響はない。
- A08a の「POST /api/cases なし」は、ページ内の `fetch` を計測用に包んで確認した（操作中の API 呼び出しは 0 件。`/api/cases` への送信も、他の API への送信もない）。画面遷移もしない。
- コンソールには Firefox の favicon 取得（CSP の `img-src` で遮断）が 2 件出る。ブラウザ自身の取得で、ページのスクリプトエラーではない（`pageerror` は 0）。v4 の Chromium では表示されなかった種類のもの。

## 4. 限界（未検証）

- **Cloudflare Access の OTP ログイン後**の本番・Staging では実行していない（人間の OTP が必要）。ローカル認証での確認である。
- 受入の他の項目（#5 / #8 など）と、既存の P0 38 件は再実行していない。今回は UI の A05 / A08a のみ。
- ブラウザは Firefox のみ。Chromium・Safari は未実行。
- 本番 DB・本番設定・Staging は変更していない。ローカル DB への書込みも、A05 / A08a の操作中には発生していない（`fetch` の計測で API 呼び出し 0 件）。
- サーバーは確認後に停止した。再実行する場合は同じ手順（ローカル設定は変更せず、ポートだけ差し替え）で行う。

## 5. リリース判定への影響

- PR-1〜3 は表示と読み取り専用 API の追加で、既存のリリース判定（`7573784` に対する条件付き GO）を覆すものではない。
- ただし、今回の受入はローカル環境の UI 2 項目だけであり、**新しいリリース判定（本番 GO）の根拠にはしない**。本番・Staging での確認と、残りの受入項目の再実行が別途必要である。
