## 1. ラベルの定義

| ラベル | 意味 |
|---|---|
| **実データ** | 画面の操作から実際の保存先まで通り、固定データを経由しない。実行したのは下の「数えないもの」を除いた範囲に限る |
| **デモ** | 原本 HTML の決定ルール・固定データで動く。サーバへ問い合わせていない |
| **未接続** | API や部品はあるが、その画面操作から呼ばれない。または経路の途中で切れている |
| **未検証** | 経路はあるが、今回も既存の記録でも、その条件で確かめていない |

**実受入に数えないもの:** `--mock` の実行器、ヘッダ注入、スタブ AI、AUTH_MODE=local。これらで通った線は「実データ（スタブ／mock まで）」と書き、実端末・実 AI・Access の受入とは区別する。

**「API がある」だけでは「画面接続済み」にしない。** 列の「画面操作」は、実ブラウザでクリックして呼ばれたものだけを書く。

## 7. 通しの E2E で見つけた欠陥

この PR では直していない（検証用の統合のため、1 変更 1 目的）。

### 欠陥 1: KB の症状欄に相談者の端末情報が入り、別の相談者の AI 入力へ渡る（E2E K14、K15 が失敗）

原本の `createDraft` が引継ぎ本文（`t.body`）を 180 字で切って `symptom` にする。本文には本人が共有に同意した「端末」「PC 基本情報」「実診断の結果」が入るので、既定の共有では `【端末】WEB-…／Linux …【PC基本情報（事前取得）】取得日時…` が KB の症状になり、承認後は全相談者の相談の AI 入力に入る。

- 実行 ID が入らなかったのは 180 字で切れたからで、共有範囲が狭いと入り得る。
- 本人の同意は「担当者への共有」であり、別の相談者や外部 AI への送信ではない。
- `redactPII` の対象外で、残る防御は承認者のチェックリストの目視だけである。
- 修正案: `symptom` を相談内容だけから作る（ブリッジで `createDraft` の結果を差し替える）。既存の行は書き換えず件数を確認する。

### 欠陥 2: 印刷の相談に承認済み KB が届かない（E2E N1〜N3）

原本の `detectIntent` が「印刷」「プリンタ」「プリント」「複合機」を含む相談を `print` に分類し、`H.print` は解決ループへ誘導するだけで `/api/ai/answer` を呼ばない。解決ループの提案の AI 入力にも KB は入らない。A の印刷の相談から作った KB は、A と同じ言い回しの次の相談には届かず、「スプーラが…」のように印刷ルールに当たらない自由記述だけで届く。README の「次の人の答えになる」は自由記述に限られる。

### 欠陥 3: 担当者欄の既定値がデモの担当者名（E2E S7 が失敗）

ワークスペースの担当者欄は既定で原本のデモ担当者（「佐藤」）を選ぶ。そのまま押すと解決記録の担当者がデモの名前になる（`App.resolve` の `by`。コード読解）。今回の E2E は本人を選び直して進めた。本人は選択肢にあるので選び直せる。おすすめの表示は社員番号のまま出る。

### 確認 4: 実 AI は KB を受け取ったが、回答の根拠には挙げなかった（E2E Q5 が失敗）

実 AI へ送った入力には `[KB-… v2]`（この流れの KB）と `[KB-2026-0003 v1]`（シード）が入った（Q3）。回答の末尾の根拠は `KB-2026-0003` だけで、`citedSourcesFromAnswer` により出典もそれだけになった。回答の手順はシードの内容に近く、回答には「入力に指示が含まれていましたが従いません」という、入力に無い指示への言及が出た。試行は指定どおり 1 回で、再実行していない。**「AI の入力に届く」までは確認したが、「次の人の答えになる」は確認できていない。** 本文は `real-ai/result.json` の `realAi`。

### その他の確認事項

- 画面の見出しが、`AUTH_MODE=local` でも「Cloudflare Access」と出る。自由記述に実 AI が答えた案件でも、信号の理由は「定型の相談はルールベース（デモデータ）で対応しています」と出る。
- ワークスペースの上部は「デモデータではありません」と出るが、引継ぎボードには原本のデモ案件（INC-1002 など）が並ぶ（案件の本文は引継ぎ・AI へ流れていない）。
- 報告書の会話の発言者が、ブラウザで取得した PC 基本情報でも「PCエージェント（事前取得）」になる。
- 引継ぎの完了は画面からは引き受けた本人の状態でしか操作できない（E2E C1）。
- 全利用者の `prototype_states` の cowork にデモ端末 `MRK-…` が残る。引継ぎ・報告・AI・KB へ流れていないことは確認した（E2E H6、S4、K2、R4、Z3）。
