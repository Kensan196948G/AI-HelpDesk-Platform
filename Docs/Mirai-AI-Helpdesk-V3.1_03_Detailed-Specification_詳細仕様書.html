3-2. 進めるSTEPの上限（到達点）

STEPバーでは、到達点までのSTEPだけを押せます。到達点は次の順に判定します。

  1. AIで解決した → 7
  2. 種類が選ばれた → 2、送信した → 3、引継ぎ済み（受付番号あり）または「解決しない」を選んだ → 4、INCができた → 5
  3. INCが解決済み → 6、ナレッジが公開された、または解決済みで下書きを作らなかった → 7

次の場合は自動で次のSTEPへ進みます：STEP 3 で受付番号ができた → 4／STEP 5 でINCが解決済みになった → 6／STEP 6 でナレッジが公開された → 7。

3-3. 信号の判定

順条件色
1完了（AIで解決／ナレッジ公開／ナレッジにしないで解決）し、種類がセキュリティでない青
2種類がセキュリティ、INCがセキュリティ事象、急ぎ、または内容に「不審・ウイルス・感染・紛失・盗難・フィッシング」を含む赤
3受付番号がある、または「解決しない」を選んだ黄
4それ以外青

4機能仕様（PC基本情報の事前取得） V3.1

V3.1で加わった仕組みの正本です。

4-1. 動きの順番

  1. 始まる時STEP 2 を開いたとき（相談する人本人・種類が選ばれている・未送信・「取得する」）。約0.2秒後に開始
  2. 集め方8分類を順に、1分類あたり約0.38秒で読み取り（全体で約3秒）。進み具合（N/8）と分類ごとの✓を表示。入力はその間も続けられる
  3. 終わった時31項目を「正常／注意／異常」で判定し、気になる点を表示。監査ログに「PC基本情報を事前取得（読み取りのみ）」を、案件・端末・項目数・気になる点の件数だけで記録（値は残さない）
  4. 送信した時取得中なら取得を終えてから、STEP 3 の最初の返答で要約（端末・時刻・項目数・気になる点の一覧・★）を示す。取得しない設定なら、その旨を表示
  5. 取り直す時「最新にする」（本人のみ）で再取得し、前回の値と比べて変わった項目を「前回から変わった点」として表示

L5SEC_DISABLE／SW_INSTALL／BULK_DELETE／PRIV_GRANTセキュリティ停止／無許可ソフト導入／一括削除／権限付与AIからは提案も作らずブロック

5-2. 実行前検証（サーバ側で行う7項目）

  1. 操作IDが許可リストに登録済み（L5ではない）
  2. 緊急停止が解除されている
  3. 本人の承認（Y）が記録されている
  4. 承認した時から操作の内容が変わっていない（承認ハッシュが一致）
  5. 対象の端末が、依頼した人に割り当てられた端末
  6. （L4のみ）IT端末管理者の承認があり、自分の申請の承認ではない
  7. 申請の状態が「実行可能」

1つでも不合格なら実行せず、端末は変更しません。実行中に緊急停止されたら中断し、失敗したら「変更なし」で止めて担当者への引継ぎを案内します。

6機能仕様（引継ぎとヘルプデスク対応）

6-2. 問い合わせ（INC）の作り方

  • 分野：引継ぎの区分（IT端末→端末、ID・アクセス権→アカウント、セキュリティ事故→セキュリティ、業務・規程／AI窓口→その他）。セキュリティの言葉があればセキュリティ。「その他・端末」は承認済みナレッジの検索結果（近さ22%以上）で分野を推定しなおす
  • 優先度：急ぎ（緊急）はP1。それ以外は緊急度「中」×影響「個人」で計算（セキュリティの疑いはP2以上）。期限はP1 1時間／P2 4時間／P3 8時間／P4 3日
  • おすすめの担当：アカウント・メール→高橋、ネットワーク→鈴木、端末・ファイル→田中、セキュリティ→伊藤、その他→佐藤（試作の例）
  • 引継ぎメモ：概要、依頼者、優先度と期限、引継ぎ理由、連携元（TKT番号と同意した情報）、AIの経過、推定分野とおすすめの担当、対象の機器・サービス、似ている未解決の問い合わせ、推奨アクション

6-3. 結果の戻し方

ヘルプデスクの状態受付番号（TKT）の状態相談した人への知らせ
引継ぎ待ち受付－
対応中（担当が決まった）対応中（担当者名）－
解決済み解決（原因と手順）チャットに「担当者が解決しました」と原因・手順
ナレッジ公開（ナレッジ番号を記録）チャットに「社内ナレッジになりました」

INC番号と受付番号の組み合わせを照合し、合わないとき（ヘルプデスク側の初期化など）は「連携先が見つかりません」と表示します。

7機能仕様（ナレッジ化）

  • 下書き：解決記録（原因・手順）と相談内容から作る。メールアドレス・IPアドレス・電話番号・パスワード等・社員番号・資産番号・依頼者と担当者の氏名を自動で隠し、隠した件数を表示。申請時にもう一度隠し漏れを確かめる
  • 登録方法：新規ナレッジ、または既存ナレッジの改訂（版が上がる）
  • 承認：申請者以外の承認者が、チェックリスト4項目（第三者が再現できる手順／機密情報がない／個人を評価・非難しない／適用範囲が明確）をすべて確認。差戻しはコメント必須
  • 反映：承認と同時にナレッジDBに保存、本棚を作りなおし、分野別のきまりの版を上げ、反映ログに記録。次の相談からAIの根拠（AI相談のナレッジ検索にも出る）
  • 見直し：利用3回以上で役に立った率60%未満は「見直し推奨」。承認者は使用停止・再開ができる

8機能仕様（運び役と外部AI）

8-1. 処理の流れ

  1. 受付を取得問い合わせ番号はAIに送らず、手元で持つ
  2. 門番：AI対象外の判定セキュリティ事象（常に対象外）、アカウントロック・パスワード、ハード故障・起動不可、権限付与・各種申請
  3. 門番：見せない所を隠す氏名・問い合わせ番号は送らない。メール・電話・IP・資産番号を隠す。パスワードらしき文字があれば送らずに停止。命令文らしき文を検出し、資料として渡す
  4. 本棚から根拠を探す承認済みナレッジを近さで探す。近さ22%未満しかなければAIを呼ばず担当者へ
  5. AIに頼む費用の上限と障害を確認してから、指示書＋根拠＋〈利用者の文章〉を送る
  6. 答えを点検出典がある／利用者にさせない操作がない／機密が入っていない／担当者への案内がある／600字以内
  7. 記録に戻す確認モードは担当者だけが見る「回答案」、直接回答モードは利用者への回答。状態は変えない
  8. 日記をつける隠した後の送信内容・根拠・AIの種類と版・指示書の版・答え・点検・費用

8-2. 設定値（試作）

設定値
回答の近さのしきい値42%以上で回答、22%〜42%で候補提示、22%未満は担当者へ
費用の上限本番 月3,000円（80%で通知）、試験 月500円（模擬の金額）
日記の保持最新300件
試験の合格条件試験問題12問で正答率90%以上、かつ隠し漏れ0件
動かし方確認モード（3a）／直接回答モード（3b）。目安：回答案の採用率が直近20件で80%以上
