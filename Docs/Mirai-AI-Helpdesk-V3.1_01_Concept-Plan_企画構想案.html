1構想の到達点

社員は1つの入口から相談し、AIが一次対応し、AIで直らなければ情報ごと人へ渡り、解決したやり方は次の人のためのナレッジになる。

AI・機械が担うこと

  • 相談の受付と、手順の案内・社内資料の検索（出典つき）
  • PC基本情報の事前取得（読み取りのみ）と、気になる点の示し方 V3.1
  • 許可リストの範囲の修復（本人のYのあと）と、実行前の検証
  • 引継ぎメモ・ナレッジ下書きのまとめ、個人情報を隠す処理
  • 外部AIへの中継（隠す・止める・根拠を添える・点検・記録）

人が決めること

  • PCを変えてよいか（本人）、設定を変えてよいか（IT端末管理者）
  • セキュリティ事故かどうか、どう対処するか
  • アカウント・権限の扱い（本人確認と所属長の承認）
  • ナレッジにしてよいか、AIへの指示書・使うAIの採用（承認者）
  • 通報・相談の扱い、人の評価・処遇（AIは関わらない）

ねらいは「AIで人を減らす」ことではありません。くり返しの質問と聞き直しをAIと事前取得で減らし、担当者が本当に人の判断が必要な相談に時間を使えるようにすることです。

3本番構成の選び方

3つの案を比べ、案Bを推奨します。機器の配置と通信の流れは詳細仕様書の1章にあります。

くらべる所案A：今のヘルプデスク＋Copilotだけ案B：AI窓口＋既存ヘルプデスク連携（推奨）案C：クラウドのITSM製品に全面移行
入口メール・電話・Teamsがばらばらステップ受付1つ（電話は代行受付）製品のポータル
PC基本情報の事前取得なし（毎回聞き出す）あり（読み取りのみ・本人が共有を選ぶ）製品の端末管理機能しだい
AIの答えの根拠Copilotの一般的な答え承認済みナレッジと社内資料（出典つき）製品のナレッジ機能しだい
安全装置（信号・許可リスト・承認）人の運用に頼る仕組みとして組み込む製品の設定で一部対応
今の台帳・手順の活用そのままdesknet's NEO AppSuiteをそのまま使う移行が必要
費用と手間小さい中（段階的に増やせる）大（ライセンス・移行）
評価聞き直しと属人化が残る効果と統制の両立。小さく始めて広げられる効果は大きいが、移行の負担と製品依存が大きい

3-2. 選ぶときの前提

  • 全社標準のAIはCopilotとし、AI窓口の追加や外部AIの利用は、社内の「生成AIに関する方針」と「生成AI利用ガイドライン」（2026年5月1日制定）にもとづく導入審査を前提にします。

4V3.1の見どころ：PC基本情報の事前取得 V3.1

V3.1で新しく加わり、効果が大きいと見込む仕組みです。項目と判定の決め方は詳細仕様書の4章が正本です。

聞き直しが減る

「PCの番号は？」「VPNは？」「再起動は？」を毎回聞かずにすみます。担当者は引継ぎの時点で、気になる点が分かっています。

AIの最初の一手が当たる

相談の言葉と項目を照らし合わせ、関係しそうな点（★）から確かめます。印刷・VPN・音声・容量・共有フォルダはとくに効果が出やすい相談です。

待ち時間を使う

相談を書いている約3秒の間に集めるので、相談する人を待たせません。

4-1. 「見張り」にしないための設計の約束

  1. 目的を限る：本人の相談に答えるためだけに使い、評価・勤怠・行動の追跡には使わない
  2. 最小限にする：PCの状態だけを取り、ファイルの中身・閲覧履歴・画面・キー入力・メール本文・個人のフォルダの一覧は取らない
  3. 本人が選ぶ：取得するか、担当者に渡すかを本人が選べる。手続きの相談では最初から取らない
  4. 見られる人を限る：本人と、共有された担当者だけ。外部AIへは識別につながる値を伏せる
  5. 記録は事実だけ：監査ログには取得したことと件数だけを残し、値は残さない

この約束は、プライバシーの尊重と、働く人が安心して相談できることを守るためのものです。本番では個人情報の取り扱いに関する社内規程に照らし、社員への説明と同意の方法をPhase 0で確定させます。

5実践の原則

旧構想の「AIが作業し、機械が確かめ、人が決める」を、問い合わせ対応に当てはめた8つの原則です。

  1. 根拠のない答えをしない承認済みナレッジと閲覧できる社内資料だけを根拠にし、出典を示す。根拠がなければ人へ渡す
  2. 読むことと変えることを分ける診断・事前取得は読み取りだけ。変えるのは許可リストの操作を、承認のあとにだけ
  3. 強い操作ほど確認を増やすL0〜L5の段階で、本人のY、管理者の承認、AIからは不可、を使い分ける
  4. 申請する人と承認する人を分ける端末操作・ナレッジ・指示書のどれも、自分の申請は自分で承認しない
  5. いつでも止められ、戻せるだれでも緊急停止でき、元に戻せる操作から始める
  6. 渡す情報は本人が決める引継ぎで何を渡すかを本人が選び、同じことを聞き直さない
  7. 社外に出すものを門番が守る隠す・止める・命令文を資料として扱う・答えを点検する、を運び役に任せる
  8. すべて記録し、改ざんを見抜くだれが・いつ・何をしたかを残し、あとから検証できるようにする

6段階導入（Phase 0〜4）

いきなり全社に広げず、効果と安全を確かめながら広げます。各Phaseの期間と目標値は、Phase 0の終わりに実績の見通しをもとに決めます。

段階目的対象・使う機能次へ進む合図（終了条件）
Phase 0
決まりを作る		本番で守るルールを、人が同じ手順で再現できる形にする信号ルール、操作許可リスト、門番のルール、AIへの指示書の初版、PC基本情報の項目と同意の取り方、試作V3.1での業務の流れの確認ルールが文書になり、関係部署（情報システム・人事・法務・労務）の確認が取れている。PCエージェントとAIの候補が決まっている
Phase 1
1部署で試す		小さく使い、答えの質と使い勝手を測るDX推進部の中だけ。読み取りと青信号の相談、運び役は確認モード回答案の採用率が目標に達し、まちがった答えの報告がない。受け入れ試験に合格
Phase 2
管理部門へ		引継ぎの往復と修復で、聞き直しが減るかを確かめる本社の管理部門。L3の修復、ヘルプデスク（INC）との連携、ナレッジ化引継ぎ後の聞き直しと解決までの時間が減っている。ナレッジの承認が回っている
Phase 3
支店・現場へ		通信が弱い所や現場の使い方でも成り立つかを確かめる支店・作業所・作業船。L4の承認、代行受付、電波の問題の切り分け現場で「使える」と確認できた。L4の承認待ちが業務を止めていない
Phase 4
育てる		品質と費用を測りながら改善を続ける直接回答モード、ナレッジの見直し、指標の定期報告、AIの切り替えの試験（継続）指標が維持・改善され、監査で指摘がない
どのPhaseでも、前のPhaseの指標（要件定義書13章）と受け入れ試験を確認してから次へ進みます。うまくいかないときは、前のPhaseに戻ってよいことにします。

8効果の見込み方

数字の目標は、Phase 1の実績を見てから決めます。ここでは「何で効果を見るか」の考え方だけを示します。

相談する人にとって

  • AIで解決した割合と、解決までの時間
  • 同じことを聞き直された回数
  • 「相談しやすくなった」という声（アンケート）

担当者・会社にとって

  • くり返しの問い合わせの減り方と、ナレッジが役に立った率
  • 事前取得の気になる点が原因だった割合
  • 1件あたりの外部AI費用、ルールが守られている度合い

指標の一覧と見るポイントは要件定義書の13章にあります。統制の枠組み（ISO/IEC 27001・20000-1、J-SOX）との対応も要件定義書の8章を参照してください。

9提言と次の一手

  1. 案Bで進めることを決める今のヘルプデスクを活かし、AI窓口を前に置く構成を基本方針とする
  2. Phase 0を始める試作V3.1をワーキンググループで実際に触り、ルール・画面・PC基本情報の項目を確認する
  3. 人と組織の合意を先に取るPC基本情報の目的と取らない情報を、関係部署と社員に説明し、同意の方法を決める
  4. Phase 1の準備DX推進部内での試しの対象・期間・目標値と、承認済みナレッジの初期登録を決める
試作V3.1は完全オフラインで、データもAIの答えも作り物です。安心して触って意見を出してもらえるよう、ワーキンググループの全員に配布することを提案します。
