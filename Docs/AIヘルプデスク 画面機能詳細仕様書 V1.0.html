1概要

1.1 目的

本書は、AIヘルプデスク サンプルアプリの全画面について、表示項目・操作・入力チェック・画面遷移・業務ルール・保存データを定義する。受付からナレッジ反映までの一連の流れ（受付 → AI一次対応 → 人間へ引継ぎ → 解決記録 → ナレッジ下書き → 人間の承認 → DB保存・AI/Skills反映）を、画面単位で再現・検証できることを目的とする。

1.2 基本方針

  • AIは回答・下書き・検査・反映処理を担当する。ナレッジの正式化（承認）は必ず人間が行う。
  • AIは承認済みナレッジだけを根拠に回答する。確度が低い場合、解決しない場合、セキュリティ事象の場合は人間へ引き継ぐ。
  • 相談者のPC情報の取得とリモート接続は、相談者の同意の確認を前提とする。
  • 申請者本人はナレッジを承認できない（職務分掌）。
  • すべての主要操作を監査ログに記録する。

1.3 前提と制約（サンプルとしての範囲）

項目本サンプルでの実装実運用時の想定
動作形態HTMLファイル1本。外部通信・外部ライブラリなしWebアプリ（サーバー＋DB）
データ保存ブラウザの localStorage（端末・ブラウザごと）業務DB（例：AppSuite、RDB）
AI回答文字バイグラム類似度とキーワード一致による疑似AILLM＋検索拡張（RAG）
PC情報固定の疑似資産データ9台＋ブラウザ実測SKYSEA Client View／Active Directory／Entra ID
リモート対応疑似（接続・実行結果とも画面上の再現）SKYSEA Client View のリモート操作など
認証操作者の選択のみ（パスワードなし）Entra ID（HENNGE One 経由）のシングルサインオン

5.3 AIの判定

条件AIの動作
セキュリティ関連語を検知カテゴリをセキュリティにし、初動手順を案内して即時に引継ぎ（推奨担当：伊藤）
最有力の一致度 42%以上そのナレッジの手順を提示
22%以上 42%未満候補を最大3件提示し、利用者が選ぶ
22%未満「ナレッジ該当なし」として引継ぎ
カテゴリが「わからない」で一致度22%以上最有力ナレッジのカテゴリを推定カテゴリとして設定

一致度の算出

  1. 問い合わせ文（件名＋内容＋追加情報＋PC診断の関連キーワード）と、ナレッジ（タイトル×2＋症状＋キーワード）を文字2文字単位に分け、コサイン類似度を求める。
  2. 類似度×0.9 に、ナレッジのキーワードが問い合わせ文に含まれる数×0.12（上限0.45）を加える。
  3. 利用3回以上のナレッジは、（有効率−0.5）×0.08 を加減する。
  4. 0〜0.96 に収め、0.05 以下は対象外とする。対象は有効ナレッジのみ。
