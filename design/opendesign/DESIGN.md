# UI 設計契約 — みらいAI窓口 × ヘルプデスク MVP

- 版: v1.0（2026-10-23）
- 設計環境: OpenDesign（project `b740d7e6-e0df-483f-91e6-32cce94c5d75`）
- Design direction: **Tech / utility**（OpenDesign 組み込み）を基調に、社内ヘルプデスク向けの navy ブランドと信号色を調整
- ビジュアル: `design-board.html`（OpenDesign artifact）
- 状態: **ユーザー承認待ち（Y/N）**

## 1. 設計原則

1. **1画面1目的**。相談者は「次にやること」が常に1つ見える。
2. **信号の3色は色だけで伝えない**。色＋日本語ラベル（青/黄/赤）＋理由を併記。
3. **AIの限界を隠さない**。「MVP: ルールベース一次対応」「デモデータ」を常時表示。
4. **担当者は情報密度重視**。ボード→案件→解決記録の順で迷わない。
5. **承認は職務分離**。自分の申請は承認できないことを UI でも明示。
6. **PC中心**。820px 以下は下部ナビ＋1カラムに落とす。
7. **キーボードで完結**。フォーカスリング、Esc でダイアログ閉止、スキップリンク。
8. **状態を設計する**。正常だけでなく、空・読込中・入力エラー・通信エラーを用意。

## 4. 画面一覧と遷移

| # | 画面 | ルート | 遷移元 → 遷移先 |
|---|---|---|---|
| S1 | ログイン | `/login` | — → ロール別ホーム |
| S2 | ホーム | `/` | ログイン後 → 新規相談 / 案件 / ボード |
| S3 | 相談ウィザード | `/consult/new` | ホーム → STEP1→2→3→(4)→S4 |
| S4 | 相談の状況 | `/cases/:id` | ウィザード完了 / ホーム一覧 |
| S5 | ボード・一覧 | `/desk` | ホーム（担当者）→ S6 |
| S6 | 案件対応 | `/desk/cases/:id` | S5 → 解決記録 → ナレッジ下書き |
| S7 | ナレッジ | `/knowledge` | ナビ → 詳細・承認 |
| S8 | 監査ログ | `/audit` | ナビ（承認者のみ） |

### 4-1. ウィザード内の状態遷移

```
STEP1 種類
  → STEP2 内容 + PC取得（取得する/しない）
  → STEP3 AI一次対応
       ├─ 解決した → STEP7 完了（チケットなし）
       ├─ 解決しない → STEP4 引継ぎ → TKT/INC発行 → STEP5 担当者
       └─ セキュリティ（赤）→ 初動手順のみ → STEP4 引継ぎ
  → STEP5 担当者が解決記録 → STEP6 ナレッジ化
  → 承認者が承認 → STEP7 完了
```

| 他人の相談を閲覧 | × | ○ | ○（参照） |

| ナレッジ下書き・申請 | × | ○ | × |

## 5. コンポーネント

| 名前 | 仕様 |
|---|---|
| Signal pill | 丸ドット＋「青 / AIで進行」「黄 / 担当者対応」「赤 / AI対象外」。理由は title 属性と本文に表示 |
| Step bar | 7 個の丸。完了=緑チェック、現在=紺、未到達=グレー。現在の STEP 名を下に表示 |
| Case card | ケース番号（等幅）、件名、相談者、信号、経過時間、担当。自分の番は左ボーダー黄 |
| PC info card | 取得日時・8分類・31項目・気になる点 N 件。進捗はカテゴリごとのチェック |
| AI message | 役割ラベル（AI / あなた / システム）、本文、根拠カード、行動ボタン。AI は「MVP」バッジ |
| Handoff memo | 共有項目、AI経過、推定分野、対象機器、推奨アクション、類似未解決 |
| Resolution form | 原因（必須）、手順（必須・複数行）、所要時間（分）。保存後に下書き生成 |
| Knowledge checklist | 再現できる / 機密がない / 個人を非難しない / 適用範囲が明確。4/4 で承認可 |
| Audit row | 時刻、操作者、操作、対象、ハッシュ（先頭12桁）。検証結果バナー |
| Toast | 成功（緑）/ 失敗（赤）。3 秒で消える。`aria-live=polite` |
| Empty state | アイコン＋1行説明＋次の行動ボタン |
| Skeleton | カード/表の骨格。`prefers-reduced-motion` でアニメーション停止 |

## 6. 状態設計

| 状態 | 表示 |
|---|---|
| Loading | スケルトン。ボタンは `aria-busy` ＋スピナー。3 秒超で「読み込みに時間がかかっています」 |
| Empty | 「まだ相談はありません」＋「新しい相談をはじめる」。ボードは列ごとの空表示 |
| Validation error | フィールド直下に赤字＋`aria-describedby`。送信ボタンは押せるが API 前に止める |
| Communication error | 上部に赤帯「通信できませんでした。再試行」＋入力内容は保持 |
| Success | トースト＋画面内の完了パネル。二重送信を防止 |
| Forbidden | 403 画面。「この操作はあなたの権限ではできません」＋ホームへ |
| Not found | 404 画面。ケース番号を表示 |

## 7. アクセシビリティ

- すべての操作要素に可視フォーカス（3px、`--brand-600`、offset 2px）。
- 信号・状態は色＋テキスト。色覚多様性に配慮。
- アイコンのみのボタンには `aria-label`。
- フォームは `label` と入力の関連付け、エラーは `role=alert`。
- ダイアログはフォーカストラップ、Esc で閉じる、閉じたら元の要素へ戻す。
- スキップリンク「本文へ移動」。
- `prefers-reduced-motion: reduce` でアニメーション・トランジションを無効化。
- タップ領域 44px 以上（SP）。

## 9. 実装との対応

| 設計 | 実装 |
|---|---|
| S1〜S8 | React Router のルート |
| Signal pill / Step bar / Case card | `components/` の共通コンポーネント |
| API 状態 | TanStack Query は使わず、薄い `useApi` フック＋明示的な loading/error |
| デザイントークン | `apps/web/src/styles/tokens.css` |
| 権限 | API のロールガード＋UI のナビ出し分け |
| PC 情報 | `pc_snapshots`（デモ生成） |
| 監査 | `audit_log` のハッシュチェーン |

## 10. 受入（UI）

1. 3 ロールでログインし、ナビと操作が変わる。
2. Flow A/B/C を最後まで操作できる。
3. 信号が業務ルール（青/黄/赤）どおりに変わる。
4. PC 情報は共有時のみ担当者に見える。
5. 承認者は自分の申請を承認できない（UI 無効＋API 403）。
6. 空・読込・入力エラー・通信エラーを確認できる。
7. 820px 以下で下部ナビになり、主要操作が可能。
8. キーボードのみで相談作成→引継ぎまで到達できる。
9. 画面に「MVP / デモデータ / ルールベース」が明記されている。
10. OpenDesign の design board と実画面の構造・色・文言が一致する（差異は docs に記録）。
