AIヘルプデスク 詳細作業手順書

問い合わせの受付から、AI一次対応、引継ぎ、解決記録、ナレッジの下書き・承認、台帳の使い方までを、画面の図と番号付きの手順で説明します。IT部門で問い合わせ対応をする人と、ナレッジを承認する人向けです。

対象：問い合わせ対応の担当者・承認者アプリ：AIヘルプデスク（外部AI連携版）V1.1前提：練習用サンプル（外部と通信しない）
本文中の点線の下線と「注」が付いたことばは、専門用語です。各章の終わりの「この章のことばメモ」と、最後の「用語集」で説明しています。ことばを押すと用語集へ移動します。

00はじめに

この手順書は、AIヘルプデスク（外部AI連携版）V1.1（以下「アプリ」）を使って、問い合わせの受付から解決、ナレッジの登録までを行うための手順です。IT部門で問い合わせ対応をする人と、ナレッジを承認する人を対象にしています。

練習用のサンプルです外部とは一切通信しません。AIの答えは、あらかじめ決めた動きで作る「模擬」です。
データはこのパソコンの中だけ入力した内容は、開いているブラウザの中に保存されます。別のパソコンには引き継がれません。
名前は架空です佐藤・鈴木・高橋などは練習用の名前です。

開き方

  1. HTMLファイルをダブルクリックします。Microsoft Edge または Google Chrome で開きます。
  2. 最初に開くと、練習用のデータ（問い合わせ・ナレッジ）が入った状態で表示されます。
  3. 画面右上の「操作者」で、自分の役割に近い名前を選びます（2章を参照）。

01全体の流れ

02画面の見方と操作者の選び方

  1. 1いまの動かし方、本番で使っているAI、AIへの指示書の版が表示されます。押すと設定画面が開きます。
  2. 2操作者を切り替えます。承認などは、承認者の名前を選んだときだけできます。
  3. 3データの書き出し・読み込みと、最初の状態に戻すボタンです。ふだんの作業では使いません（運用管理手順書で説明）。
  4. 4左のメニューで画面を切り替えます。上から作業の順番に並んでいます。
  5. 5数字は、その画面で待っている件数です。赤い数字は急ぎ（P1や期限超過、承認待ち）があることを表します。
  6. 6①〜⑦のカードは、各段階に何件あるかを表します。押すとその画面に移ります。
  7. 7運び役の状況です。動かし方、本番のAI、今月のAIの費用が分かります。
  8. 8問い合わせの一覧です。行を押すと、右から詳細（経過や関連付け）が開きます。

03作業1　問い合わせを受け付ける

  1. 1練習用のサンプルボタンです。押すと件名と内容が自動で入ります。
  2. 2依頼者の部署と名前、受付の方法（ポータル・メール・Teams・電話）を入れます。
  3. 3分野が分からないときは「わからない（AIが推定）」のままにします。
  4. 4緊急度と影響範囲を選ぶと、優先度が自動で決まります。
  5. 5件名は「何が・どうなった」を短く書きます。
  6. 6内容は「いつから・何をしたら・どうなるか」を書きます。表示されたエラーの文はそのまま書き写します。
  7. 7パスワードは絶対に書きません。書かれていると門番がAIに送るのを止めます。
  8. 8押すと受付が終わり、運び役が動き出します。

手順

  1. 左のメニューから① 受付を開きます。
  2. 依頼者・受付の方法・分野・緊急度・影響範囲を選びます。
  3. 件名と内容を入力します。練習ではサンプルボタンを押してもかまいません。
  4. 受付して運び役に渡すを押します。
  5. 自動で② 運び役・AI一次対応に移り、AIの処理が始まります（4章へ）。

優先度の決まり方

緊急度＼影響範囲個人部署全社

中P4P3P2
低P4（最も低い）P4P3

対応期限は、P1が1時間、P2が4時間、P3が8時間、P4が3日です。不審メールでリンクを開いた・パスワードを入力したなど被害の可能性がある場合は、自動でP1になります。

入力してはいけないもの：パスワード、暗証番号、他人の個人情報。誤って書いた場合も、アプリはAIに送らず担当者へ回しますが、受付の記録には残ります。気づいたら担当者に伝えてください。

04作業2　AI一次対応を見守る

受付が終わると、運び役が図4の順に処理します。途中の門番・本棚・点検のどこかで条件に合わないと、そこで止まって担当者へ回ります。AIの答えをそのまま信じないための仕組みです。

  1. 1左は問い合わせの一覧です。選ぶと右に内容が出ます。
  2. 2利用者が書いた内容です。
  3. 3AIの答えです。最後の「出典」は、答えの元になったナレッジの番号です。
  4. 4手順で解決したら、利用者がこのボタンを押します。
  5. 5解決しないときに押すと、担当者へ引き継がれます。
  6. 6近い候補がほかにもあるときに表示されます。
  7. 7エラーの文など、追加の情報を送ると、運び役がもう一度調べます。
  8. 8運び役が各段階で何をしたかの記録です。ボタンで、AIに送った内容と答え、点検結果を見られます。

手順（直接回答モードのとき）

  1. 受付の後、AIの答えが表示されるまで数秒待ちます。
  2. 答えの手順を、利用者に順番に試してもらいます。
  3. 解決したら✔ この手順で解決したを押します。状態が「AI解決」になり、このナレッジの役に立った率が上がります。
  4. 解決しなければ✖ 解決しない → 担当者へ引継ぎを押します。引継ぎメモが自動で作られ、③ 引継ぎ・④ 解決記録に移ります。
  5. ほかの候補を試したいときは他の候補を見るを押します。エラーの文が分かったら、下の欄に入力して送信を押します。
確認モードのとき：確認モードでは、AIの答えは利用者に表示されません。「AIが作った回答案を担当者が確認してから連絡します」と表示され、そのまま担当者へ引き継がれます。担当者は5章の手順で回答案を確かめます。

05作業3　引き継いで対応する

  1. 1引継ぎ待ちと対応中の問い合わせです。急ぎ（優先度が高く、期限が近い）順に並びます。
  2. 2引継ぎメモです。経過を読めば、利用者に同じ説明を求めずに済みます。
  3. 3確認モードのときだけ表示される「AIの回答案」です。使えたかどうかを評価します。
  4. 4担当者を選んで対応を始めます。AIのおすすめが初めから選ばれています。
  5. 5対応を始めると、解決記録の入力欄が表示されます（6章）。
  6. 6チェックを入れたままにすると、解決の記録からナレッジ下書きが自動で作られます。
  7. 7記録を保存するボタンです。練習用の記入例や、AIの回答案の手順を入れるボタンもあります。

手順

  1. ③ 引継ぎ・④ 解決記録を開き、左の一覧から問い合わせを選びます。
  2. 引継ぎメモを読みます。試したナレッジ、利用者の答え、おすすめの担当、対応期限が書かれています。
  3. 確認モードのときは、AIの回答案を読み、使えたか使えなかったを押します。この評価は回答案の採用率として集計されます。
  4. 「担当者」で担当を選び、担当して対応開始を押します。
  5. 必要に応じて、利用者に連絡して対応します。セキュリティ事象のときは、証拠を残すことと影響範囲の確認を優先します。
  6. 解決したら6章の手順で記録します。
似た問い合わせが同時に来ているとき：引継ぎメモに「似ている未解決の問い合わせ」が出たら、同じ原因の可能性があります。10章の手順で親の問い合わせ／子の問い合わせとしてまとめると、まとめて解決できます。

06作業4　解決を記録する

手順

  1. 対応中の問い合わせを選ぶと、「④ 解決記録」の入力欄が表示されます（図6の5）。
  2. 「原因」に、何が原因だったかを事実だけ書きます。
  3. 「対応手順」に、行った操作を1行に1つずつ書きます。別の担当者が読んで同じ操作ができる細かさで書きます。
  4. 所要時間（分）と、必要なら備考・再発防止を入力します。
  5. ナレッジにする価値があるときは、「この解決内容からナレッジ下書きを作成する」にチェックを入れたままにします。
  6. 解決を記録を押します。チェックを入れていた場合は、自動で⑤ ナレッジ下書きに移ります。

項目よくない例よい例

07作業5　ナレッジ下書きを整えて申請する

ナレッジ下書きは、解決記録から自動で作られます。このとき、名前・メールアドレス・電話番号などは自動で隠されます。担当者は内容を読みやすく整えてから承認を申請します。

手順

  1. ⑤ ナレッジ下書きを開き、左の一覧から下書きを選びます。
  2. 上に出る「個人情報・機密情報を自動で隠しました」の表示を確認し、隠し残しがないか本文を読みます。
  3. タイトルを「利用者が困ったときに検索しそうな言葉」に直します。例：「DirectCloudドライブの同期が止まりエラーが表示されるときの対処」
  4. 「分野（反映先のきまり）」を確かめます。選んだ分野の分野別のきまりにナレッジが加わります。
  5. 「登録方法」で、新しいナレッジにするか、既存のナレッジの改訂にするかを選びます。AIが案内したナレッジで解決しなかった場合は、その改訂を検討します。
  6. 症状・原因・対応手順・キーワードを整えます。
  7. 下書き保存で途中を保存できます。仕上がったら承認申請を押します。
項目書き方
タイトル利用者の言葉で。エラーの文があればそのまま入れる
症状利用者から見えること（画面に何が出るか）
原因分かっている事実だけ
対応手順1行に1つの操作。管理者だけができる操作は「管理者が〜」と書く（AIはその手順を利用者向けから分けて扱う）
キーワード製品名・エラーの文・言い換え（例：受信できない、届かない）をカンマで区切る。AIが本棚から探すときの手がかりになる
差し戻されたとき：一覧で「差戻し」と表示され、承認者のコメントが上に出ます。コメントに沿って直し、もう一度承認申請します。

08作業6　ナレッジを承認する（承認者）

承認者は、申請されたナレッジ下書きを4つの観点で確かめ、承認するか差し戻します。承認すると、ナレッジはすぐに本棚に入り、次の問い合わせからAIの根拠になります。間違ったナレッジが広まらないよう、承認は必ず人が行います。

手順

  1. 画面右上の「操作者」で、承認者（渡辺または山本）を選びます。申請した本人は承認できません。
  2. ⑥ 承認者の確認を開き、左の一覧から承認待ちを選びます。
  3. 既存ナレッジの改訂の場合は、「現行」と「改訂案」が左右に並ぶので、違いを確かめます。
  4. 下の4つのチェック項目を読み、すべて満たしていればチェックを入れます。
  5. 問題がなければ承認してDB保存・本棚に反映を押します。反映の様子が順番に表示されます。
  6. 直してほしい点があれば、コメントに理由を書いて差戻しを押します。差戻しのときはコメントが必須です。
  7. 承認後に受付で反映を試すを押すと、似た問い合わせを入れた受付画面が開き、AIが新しいナレッジを使うことを確かめられます。

承認のチェック項目

チェック項目見るところ
技術的に正確で、第三者が再現できる手順になっている手順を読んだだけで、別の担当者が同じ操作をできるか
個人情報・認証情報・IPアドレス等の機密情報が含まれていない名前、パスワード、サーバ名、IPアドレスが残っていないか
特定の個人を評価・非難する記述がない「〇〇さんの操作ミス」のような書き方がないか
適用範囲（対象拠点・端末・バージョン）が明確である「本社2階のみ」など、どこで使える手順かが書かれているか
差戻しコメントの例：「手順3が本社2階の複合機だけの内容になっています。全拠点で使える書き方にするか、対象の拠点を明記してください。」
この章のことばメモ
本棚
承認済みのナレッジの置き場所です。AIは自分の知識ではなく、本棚から選ばれたナレッジを読んで答えます。
根拠
AIが答えるときに読むナレッジのことです。根拠が見つからないときは、AIを呼ばずに担当者へ回します。

09作業7　ナレッジを探す・使用停止にする

ナレッジを探す

  1. ⑦ ナレッジDB（本棚）を開きます。
  2. 検索欄にタイトル・症状・キーワードの一部を入れます。分野でも絞り込めます。
  3. 表の「役に立った率」が低く「見直し推奨」と出ているナレッジは、改訂を検討します。
  4. 行を押すと、本文・版の履歴・元になった問い合わせ・関連付けが表示されます。

AIが今どう答えるかを確かめる

  1. ⑦ 本棚・分野別のきまりを開きます。
  2. 「本棚の検索テスト」に問い合わせの文を入れ、本棚を検索を押します。
  3. どのナレッジがどれだけ近いか、AIが「答える・候補を出す・担当者へ回す」のどれになるかが表示されます。この検索ではAIは呼びません。

古くなったナレッジを使用停止にする（承認者のみ）

  1. 操作者を承認者にします。
  2. ナレッジの詳細を開き、使用停止にする（AIの答えに使わない）を押します。
  3. ナレッジは消えずに残り、使用停止の状態になります。AIの根拠からは外れます。戻すときは「使用停止中も表示」にチェックを入れて探し、使用を再開を押します。
この章のことばメモ
役に立った率
ナレッジを案内した後、利用者が「解決した」と答えた割合です。低いナレッジは見直します。
近さ（一致度）
問い合わせの文章とナレッジがどれだけ似ているかの目安（0〜100%）です。42%以上で答え、22〜42%は候補を出し、22%未満は担当者へ回します。
使用停止（アーカイブ）
ナレッジを消さずに、AIの答えに使わないようにすることです。あとで再開できます。

10作業8　問い合わせをまとめる

問い合わせ台帳は、すべての問い合わせの記録です。同じ原因の問い合わせを親の問い合わせ／子の問い合わせとしてまとめたり、重複をつないだりできます。

同じ原因の問い合わせをまとめる

  1. 問い合わせ台帳を開きます。
  2. まとめたい問い合わせの行頭のチェックを入れます（複数）。
  3. 上に出る帯の「親」で代表の問い合わせを選び、選択を子として紐付けを押します。
  4. 親の問い合わせを「解決を記録」するとき、「子の問い合わせも同じ解決内容で一括解決する」にチェックを入れると、子もまとめて解決します。

1件ずつ関連付ける

  1. 問い合わせの行を押して詳細を開きます。
  2. 「関連付け」の欄で、相手の番号（INC-…、KB-…、CI-…）を入力します。
  3. 関連の種類（関係する問い合わせ・親・重複など）を選び、メモを書いて関連付けを押します。
  4. AIが見つけた候補（似ている問い合わせ・ナレッジ・機器）も表示されます。決めるのは人です。
Excelで見るには：Excel用に書き出す（CSV）を押すと、絞り込んだ一覧をCSVファイルで保存できます。
この章のことばメモ
親の問い合わせ／子の問い合わせ
同じ原因で複数の問い合わせが来たとき、代表の1件を「親」、残りを「子」としてまとめる仕組みです。親を解決すると子もまとめて解決できます。
重複
同じ内容の問い合わせが二重に登録されたものです。元の問い合わせにつなげて管理します。
CSV
Excelで開ける表の形式です。書き出したファイルをダブルクリックするとExcelで開けます。

11作業9　機器・サービスの影響範囲を見る

機器・サービス台帳は、社内の機器・サービスと、そのつながりをまとめた台帳です。あるサービスが止まったときに、どこまで影響範囲が広がるかを確かめられます。

影響範囲を確かめる

  1. 機器・サービス台帳を開き、「つながりと影響範囲」のタブを押します。
  2. 「影響を調べる機器・サービス」で対象を選びます。
  3. そのサービスを使っている機器・サービスと、それぞれの未解決の問い合わせが一覧で表示されます。
  4. 原因の候補として、対象が使っている側の機器・サービスも表示されます。

新しい機器・サービスを登録する

  1. 「機器・サービス一覧」のタブを開きます。
  2. 下の「機器・サービスを追加」で、名称・種別・管理担当・判定に使う言葉（カンマ区切り）を入力します。
  3. 追加を押すと、過去と今後の問い合わせが判定の言葉で自動的に紐付けられます。
この章のことばメモ
機器・サービス（構成アイテム）
台帳に載っている一つひとつのサービスや機器のことです。例：Microsoft 365、Entra ID、VPN、複合機。
機器・サービス台帳（CMDB）
社内のサービス・システム・機器と、そのつながりをまとめた台帳です。英語の略で「CMDB」と呼びます。
影響範囲
ある機器・サービスが止まったときに、困る人や、一緒に止まる他のサービスの広がりのことです。

13困ったとき

困りごと原因と対処
承認のボタンが押せない操作者が承認者ではないか、申請者本人です。画面右上で別の承認者を選びます。
AIの答えが表示されない確認モードになっている可能性があります。画面右上の表示を確かめます。確認モードでは答えは担当者側（③の画面）に出ます。
すぐに担当者へ回ってしまう「運び役の処理」を開き、どこで止まったかを確かめます（4章の表）。パスワードの記載、根拠なし、AI対象外などが理由です。
同じ問い合わせが何件も来ている10章の手順で親と子にまとめます。機器・サービス台帳で影響範囲も確かめます。
ナレッジが古くて間違っている承認者に連絡し、改訂の下書きを作るか、使用停止にします（9章）。
入力した内容が消えたブラウザの履歴やサイトデータを消すと、データも消えます。管理者が書き出したファイルから戻せる場合があります（運用管理手順書）。
間違えてパスワードを書いてしまったAIには送られていません（門番で停止）。担当者に伝え、パスワードを変更してもらいます。
