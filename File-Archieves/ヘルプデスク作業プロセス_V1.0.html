ヘルプデスク作業プロセス

推奨構成（受付と記録はAppSuite、一次対応とナレッジ下書きはLightblue、引継ぎ後は担当者、ナレッジ化は人の承認）で運用したときの作業手順です。誰が、どのシステムで、何をして、どの状態にしたら次へ渡すかを工程ごとに定めます。期限は運用開始時に決めるための案です。

01全体の流れ

横軸が時間の流れ、縦の帯が実施者・システムです。番号は「02 工程別の作業」と対応します。赤の経路はAIを通さず担当者へ回す案件、破線は差戻しと月次の作業です。

02工程別の作業

実施者で絞り込み
No工程実施者システム作業内容記録・次へ渡す条件期限（案）
1問合せ登録利用者NEOポータル → AppSuite受付フォーム問合せ種別・製品・症状・エラー内容・資産番号を選択または入力する。パスワードや管理用アカウントの情報は書かない必須項目を入力して登録—
2受付・判定AppSuite（自動）担当者AppSuite自動採番と登録通知。種別がAI対象外（03参照）なら担当者へ回す。それ以外は利用者へLightblue一次対応アシスタントの案内を表示・通知する状態を「AI確認中」または「担当者対応中」にする即時
3一次回答を試す利用者Lightblue 一次対応アシスタント症状・製品・エラー内容だけを入力し、回答の手順を試す。氏名・連絡先・パスワードは入力しない—受付当日中
4結果を記録利用者AppSuite受付データで「AI解決」か「未解決」を選ぶ。役立った回答に出典のナレッジIDがあれば記録する。未選択のまま期限を過ぎた案件は、担当者が日次の滞留確認で拾う状態を「AI解決」または「担当者対応中」にする受付から1営業日
5AI解決で完了担当者AppSuite「AI解決」の案件を日次で確認する。回答が誤っていた・古かった場合は元のナレッジを修正対象にする対応結果「AI解決」で完了翌営業日
6割当・対応有藤／砂子AppSuite・NEO通知通知を受けて担当者欄に自分を割り当てる。リモート対応・訪問・ベンダー連絡を行う。セキュリティ事象はセキュリティ事象アプリに起票して初動を優先する状態「担当者対応中」。利用者の作業待ちは「利用者確認待ち」初回連絡は当日中
7解決記録担当者利用者AppSuite原因カテゴリ・原因の確度・対応結果・手順を入力し、利用者に解決を確認する。再発パターンなら問題管理に紐づける。ナレッジ候補か判定する必須項目を入力してクローズ。ナレッジ候補は「候補」に解決後1営業日
8下書き作成担当者Lightblue 下書きアシスタント解決記録から氏名・資産番号・アカウント名・サーバパスを除いた内容を渡し、決まった見出し（症状／原因／手順／対象者）で下書きさせる。内容を人が確認する—候補判定から1週間
9下書き登録担当者AppSuite ナレッジ下書きを登録し、関連案件ID・製品・原因カテゴリ・対象者のタグを付ける状態を「レビュー中」にする8と同日
10承認承認者AppSuite（またはNEOワークフロー）手順の正確さ・再現性、個人情報や認証情報が残っていないか、公開範囲を確認して承認または差戻しする状態「承認」、承認者・承認日を記録。差戻しは理由を書いて8へレビュー開始から1週間
11参照データへ反映管理者AppSuite → 参照データの保管先承認済みナレッジを1ナレッジ1ファイルで出力し、Lightblueが参照する保管先に置く。廃止分は削除する。利用者向けの内容はNEOポータルのFAQにも載せる状態「反映済み」、反映日を記録週次
12Skills更新・周知管理者Lightblue 管理画面・NEOインフォメーション月次レビューの結果から、一次対応の手順・判断ルール（AI対象外の条件など）を更新する。多発している事象はインフォメーションで周知する更新内容と日付を履歴に残す月次

03AIを通さず担当者へ回す案件

受付フォームの種別で判定し、工程2から直接6へ進めます。生成AI利用ガイドライン第6条の入力禁止情報（個人情報・認証情報・脆弱性やマルウェアの情報）に触れやすい案件と、AIでは解決できない案件です。

種別担当者の初動理由
セキュリティ事象端末をネットワークから切り離すよう案内し、セキュリティ事象アプリに起票初動の速さが必要。脆弱性・マルウェアの情報はAIに入力しない
アカウントロック・パスワード本人確認のうえ管理用アカウントで解除認証情報の入力を誘発する。利用者側では解決できない
ハード故障・起動不可代替機の手配、メーカー修理の手配利用者の操作では解決しない
拠点・全社に影響する障害影響範囲の確認とNEOインフォメーションでの周知個別回答より復旧と周知が優先
権限付与・各種申請NEOワークフローの申請を案内承認が必要なため

04状態の遷移

問合せ 受付→AI確認中→AI解決（完了） AI確認中で未解決になった場合、またはAI対象外の場合は、下の流れに移ります。
　 担当者対応中⇄利用者確認待ち→完了／未解決クローズ 未解決クローズは、原因不明のまま利用者の了承を得て閉じる場合に使います。問題管理に紐づけて再発を追います。
ナレッジ 候補→下書き→レビュー中→承認→反映済み→廃止 差戻しはレビュー中から下書きへ戻します。廃止したナレッジは参照データからも削除します。状態「承認」への変更は承認者だけができるよう権限を設定します。

05定常業務

頻度実施者作業
毎日（朝・夕）担当者AI確認中のまま期限を過ぎた案件、担当者未割当の案件、利用者確認待ちが長い案件を確認する。前日のAI解決案件の内容を確認する
毎週管理者承認者承認済みナレッジを参照データへ反映し、廃止分を削除する。レビュー中のまま止まっているナレッジを確認する
毎月管理者担当者受付件数、AI解決率、引継ぎまでの時間、平均解決日数、ナレッジの承認件数と差戻し率を集計する。AIの誤回答の事例を確認し、ナレッジとSkillsを直す。資産マスタを再取り込みする
四半期管理者問題管理の恒久対策の進捗を確認する。AI対象外の条件と期限（案）を見直す

06自動化した場合に変わる工程

第2・3段階で中継処理を入れた場合です。人の作業が減る工程と、残る工程を示します。承認（工程10）は自動化しません。
