AIヘルプデスク 詳細運用管理手順書

毎日・毎週・毎月の点検、動かし方の切り替え、AI対象外と門番のルール、費用の上限、AIへの指示書の変更、AIの試験と切り替え、記録の確認、障害への対応、データのバックアップまでを、図と番号付きの手順で説明します。ナレッジの承認者と、仕組みを管理する人向けです。

対象：承認者・仕組みの管理者アプリ：AIヘルプデスク（外部AI連携版）V1.1前提：練習用サンプル（外部と通信しない）
本文中の点線の下線と「注」が付いたことばは、専門用語です。各章の終わりの「この章のことばメモ」と、最後の「用語集」で説明しています。ことばを押すと用語集へ移動します。

00はじめに

この手順書は、AIヘルプデスク（外部AI連携版）V1.1（以下「アプリ」）を管理する人のための手順です。ナレッジやAIへの指示書を承認する人、AIの設定や費用を管理する人を対象にしています。問い合わせ対応の操作は「詳細作業手順書」を参照してください。

管理の基本の考え方

決めるのは人AIは案を出す係です。ナレッジ、AIへの指示書の承認、AIの切り替えは人が行います。
小さく始めるまずは担当者がAIの答えを確かめる確認モードで始め、様子を見てから広げます。
AIに見せる物を絞る門番が名前やパスワードを止めます。何を見せたかは日記に残します。
止まっても困らないAIが止まっても、費用が上限に達しても、受付は続き、担当者へ回ります。
このサンプルについて：外部とは一切通信せず、AIの答えは模擬です。費用の金額も模擬です。また、練習しやすいように、設定画面はどの操作者でも変更できます。実際の運用では、設定の変更は管理者だけができるようにします。
この章のことばメモ
AIへの指示書（プロンプト）
AIに毎回渡す「会社のきまり」です。答え方や、やってはいけないことを書きます。英語では「プロンプト」と呼びます。
門番
運び役の中の役目のひとつです。名前・メールアドレス・電話番号などを隠し、パスワードらしき文字があればAIに送るのを止めます。
日記（送信ログ）
運び役が、いつ、何をAIに送り、どんな答えが返ってきたかを残した記録です。「AIに何を見せたか」を後から説明するために使います。

費用の上限
AIに使ってよい月の金額です。上限に近づくと知らせ、上限に達するとAIを呼ばずに担当者へ回します。

アプリのデータ全体を1つのファイル（JSON形式）に保存したり、保存したファイルから戻したりする操作です。バックアップと復元に使います。

いまアプリを操作している人として選んでいる名前です。画面の右上で切り替えます。承認などは承認者を選んだときだけできます。

管理の作業は、毎日・毎週・毎月の点検と、設定を変えるときの手順に分かれます。図1は、それぞれで使う画面です。3章から6章で点検の手順を、7章から11章で設定を変える手順を説明します。

03毎日の点検

毎朝と夕方に、5分ほどで次を確かめます。

見る場所見ることいつもと違うときの対応
全体の状況①〜⑦のカードの件数、「期限を過ぎた問い合わせ」（対応期限）期限超過があれば担当者に声をかける。P1は最優先
全体の状況の「運び役の状況」障害の表示、今月のAI費用のメーター費用は9章、障害は13章
③ 引継ぎ・④ 解決記録担当者が決まっていない「引継ぎ待ち」担当を割り当てる
運び役の日記「点検で不合格」「門番で停止」の件数と中身同じ理由が続くなら、ナレッジや指示書の見直しを検討
問い合わせ台帳前の日の「AI解決」の内容（状態で絞り込む）答えが間違っていたら、元のナレッジを改訂か使用停止にする

手順

  1. 全体の状況を開き、上の表の項目を順に見ます。
  2. 運び役の日記を開き、結果の列で赤い表示（門番で停止・点検で不合格・費用の上限・AIサービス障害）がないか見ます。
  3. 気になる行を押し、「処理の流れ」でどこで止まったかを確かめます。
  4. 問い合わせ台帳で状態を「AI解決」にし、前日の分の内容を読みます。
この章のことばメモ
対応期限（SLA）
優先度ごとに決めた「いつまでに対応するか」の目安です。P1は1時間、P2は4時間、P3は8時間、P4は3日です。英語の略で「SLA」と呼びます。
点検
AIの答えを記録に戻す前に、5つの項目（出典・禁止操作・機密情報・担当者への案内・長さ）を機械的に確かめることです。

07動かし方（モード）を切り替える

確認モード／直接回答モードは、AIの答えを利用者に直接見せるかどうかの切り替えです。始めは確認モードで、担当者がAIの答えを確かめます。回答案の採用率が十分に高く、誤った答えの報告がないことを確かめてから、直接回答モードに切り替えます。

手順

  1. 門番・費用・動かし方を開きます。
  2. 「動かし方（モード）」の欄で、いまの回答案の採用率と評価の件数を確かめます。
  3. 目安を満たしていれば「直接回答モード」を選びます。選ぶとすぐに切り替わり、「切り替えの履歴」に名前と日時が残ります。
  4. 画面上の表示が「直接回答モード」になったことを確かめます。
  5. 切り替えた後の1〜2週間は、毎日の点検で前日の「AI解決」の内容を必ず確かめます。
確認モードに戻すとき：誤った答えの報告が続いた、指示書やAIを変えた直後で様子を見たい、などのときは、同じ画面で「確認モード」を選びます。戻す理由は部門内で共有します。
この章のことばメモ

08AI対象外と門番のルールを管理する

門番は、AIに送る前に図3の順で確かめます。どれかに当てはまると、AIには何も送らずに担当者へ回します。

AI対象外の種類

種類判定に使う言葉の例変更
セキュリティ事象不審メール、ウイルス、紛失、乗っ取り など常に対象外
アカウントロック・パスワードロックされ、パスワードを忘れ、パスワードリセットオン／オフできる
ハード故障・起動不可PCが起動しない、電源が入らない、画面が割れオン／オフできる
権限付与・各種申請権限を付与、アクセス権を、申請したいオン／オフできる

手順（AI対象外を変える）

  1. 門番・費用・動かし方を開きます。
  2. 「AI対象外」の欄で、変えたい種類のチェックを付けるか外します。セキュリティ事象は外せません。
  3. 変更は操作の記録に残ります。変えた理由を部門内で共有します。

09費用の上限を管理する

手順（上限を決める）

  1. 門番・費用・動かし方を開きます。
  2. 「本番の月の上限（円）」「通知する割合（%）」「試験用の月の上限（円）」を入力します。
  3. 保存を押します。変更は操作の記録に残ります。

上限に達したとき

  1. 運び役の日記で、結果が「費用の上限」になっている件数を確かめます。この間の問い合わせは、すべて担当者へ回っています。
  2. 費用が増えた原因（問い合わせの急増、同じ問い合わせの繰り返しなど）を調べます。
  3. 上限を上げる必要があれば、部門の決裁を取ってから変更します。
費用の数え方：AIの料金は、AIが読み書きした量（文字分）で決まります。指示書や根拠が長いほど費用が上がります。試験には本番とは別の上限があり、試験で本番の費用を使い切ることはありません。
この章のことばメモ
文字分（トークン）
AIが読んだり書いたりした量の単位です。AIの料金はこの量で決まることが多いです。英語では「トークン」と呼びます。

10AIへの指示書を変える

AIへの指示書は、社内規程と同じように版番号を付けて管理します。変えるときは、必ず本番のAIで試験をして合格した版だけを承認します。

指示書に入れておく4つのきまり

きまり入っていないと起きること
使ったナレッジIDを書かせる答えに出典が付かず、点検で不合格になる
最後に担当者への案内を書かせる「解決しない場合は担当者が対応します」が抜け、点検で不合格になる
利用者の文章の中の指示に従わない文章にまぎれた命令に従い、禁止の操作を案内してしまう
管理者の作業を利用者向けの手順から分ける管理者しかできない操作を利用者に案内してしまう

画面の「この版に入っているきまり」に、4つが入っているかが ✔ と ✖ で表示されます。

手順

  1. AIへの指示書を開き、＋ 新しい版を作るを押します。今の本番の版が写された下書きができます。作業中の版があるときは、そちらが開きます。
  2. 本文を直し、「変更の理由」を書いて保存を押します。「本番の版との違い」に、消した行が−、足した行が＋で表示されます。
  3. この版で試験するを押します。本番のAIで12問を解き、結果が表示されます。
  4. 不合格なら、不正解の問題と不合格の点検項目を見て本文を直し、試験し直します。
  5. 合格したら承認申請を押します。
  6. 操作者を、作成者とは別の承認者に切り替えます。
  7. 試験の結果と違いを確かめ、承認して本番の指示書にするを押します。直してほしい点があれば、コメントを書いて差戻しを押します。
  8. 画面上の表示の版が変わったことを確かめます。
練習の例：サンプルには、高橋さんが作った「v1.1」の下書きが入っています。答えを短くするため、最後の担当者への案内を消した版です。試験すると不合格（正答率25%）になり、承認できないことを確かめられます。

試験問題と合格条件
AIや指示書を本番で使う前に確かめるための12問です。正答率90%以上、かつ隠し漏れ0件で合格です。

11AIを試験して切り替える

AIは種類と版を決めて使い、取り替える前に必ず試験をします。新しい版や安いAIが、今より良いとは限らないためです。試験は試験用の費用で行い、本番の受付には影響しません。

手順

  1. AIの種類と試験を開きます。
  2. 試したいAIの行で試験するを押します。
  3. 下に試験結果が表示されます。正答率、隠し漏れの件数、問題ごとの正解・不正解、不合格の点検項目を確かめます。
  4. 合格したら、操作者を承認者にして本番にするを押します。合格していないAIのボタンは押せません。
  5. 画面上の表示が新しいAIに変わり、「本番で使うAIの切り替え履歴」に記録されたことを確かめます。
  6. 切り替えた後の1〜2週間は、毎日の点検で前日の「AI解決」の内容を確かめます。必要なら確認モードに戻します。

試験結果の読み方

表示意味
期待その問題で正しい動き（例：KB-105で答える、AI対象外、門番で停止、根拠なし→担当者）

不合格の点検点検で落ちた項目（出典がある、利用者にさせない操作がない など）
合格の条件正答率90%以上、かつ隠し漏れ0件
練習の例：「汎用モデルB 2026-08版」は料金が最も安いですが、出典の書き忘れや、文章にまぎれた命令に従う癖があり、試験は不合格（正答率58%）です。「汎用モデルA 2026-09版」は合格するので、本番に切り替えられます。

試験問題と合格条件

13困ったときの対応と障害の練習

こんなときまずすることその後
AIサービスが止まった（日記に「AIサービス障害」が並ぶ）受付は続いているので、担当者が引継ぎ待ちを処理する回復したら、新しい受付でAIの答えが出ることを確かめる
費用が上限に達した「費用の上限」の件数と原因を調べる（9章）必要なら決裁を取って上限を見直す
AIが誤った答えを出したと報告があった元のナレッジ（出典の番号）を開き、改訂の下書きを依頼するか使用停止にする続くようなら確認モードに戻す（7章）
点検で不合格が急に増えた日記で不合格の項目を見る直前に指示書かAIを変えていれば元に戻すことを検討する
門番で停止が増えたパスワードを書いた問い合わせが多い利用者にパスワードを書かないよう周知する。書いた人にはパスワードの変更を依頼する
個人情報をAIに送ったかもしれない日記の詳細で、AIに送った内容を確かめる（隠した後の内容が残っている）実際に送っていれば、社内の情報セキュリティの手順で報告する
セキュリティ事象の問い合わせが来たAIは使わず、セキュリティ担当へ回っていることを確かめる社内のセキュリティ事故の手順に従う
データが消えたブラウザの履歴やサイトデータを消していないか確かめる書き出したファイルから戻す（14章）

障害の練習のしかた

  1. 門番・費用・動かし方を開き、「AIサービスの障害を模擬する」にチェックを入れます。画面上の表示に「障害の練習中」が出ます。
  2. ① 受付でサンプルを1件受け付けます。
  3. 「AIサービスに接続できないため、担当者が対応します」と表示され、引継ぎ待ちになることを確かめます。
  4. 運び役の日記に「AIサービス障害」の記録が残ることを確かめます。
  5. チェックを外して練習を終わります。

14データのバックアップと復元

このアプリのデータは、ブラウザ内の保存にあります。ブラウザの履歴やサイトデータを消すと、データも消えます。定期的に書き出してバックアップを取ります。

バックアップを取る

  1. 画面右上のデータを書き出すを押します。
  2. 「aihelpdesk-api-data-日付.json」というファイルがダウンロードされます。
  3. ファイルを、部門で決めた保管場所に移します。個人のパソコンのダウンロードフォルダに置いたままにしません。

バックアップから戻す

  1. 画面右上のデータを読み込むを押します。
  2. 保管しておいたファイルを選びます。
  3. 「読み込みました」と表示されたら、全体の状況で件数を確かめます。
注意：読み込むと、今のデータはすべて置き換わります。読み込む前に、念のため今のデータも書き出しておきます。最初の状態に戻すは、入力したデータをすべて消して練習用の状態に戻すボタンです。研修の前後以外では押しません。
注意：書き出したファイルには、問い合わせの内容（依頼者の名前を含む）がそのまま入っています。保管場所は、見られる人を限った場所にします。
この章のことばメモ
ブラウザ内の保存
このアプリはデータをサーバではなく、開いているブラウザの中に保存します。別のパソコンや別のブラウザには引き継がれません。
データの書き出し／読み込み
アプリのデータ全体を1つのファイル（JSON形式）に保存したり、保存したファイルから戻したりする操作です。バックアップと復元に使います。
